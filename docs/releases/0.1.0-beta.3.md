03.11.2026, 12:43:13 UTC. **Опубликован [GitHub prerelease v0.1.0-beta.3](https://github.com/QahNaaRlN/ouro/releases/tag/v0.1.0-beta.3).** Рабочая локальная установка обновлена с сохранением прежней базы. Source commit — [`93d42be34478c49e07f9074face79806f1d7e274`](https://github.com/QahNaaRlN/ouro/commit/93d42be34478c49e07f9074face79806f1d7e274); annotated tag `5987b4229313203368c2bec8f45dd66fac95c9a3` указывает на этот commit.

Выпуск объединяет проектные и auth-исправления прежнего PR №20 (`918aadd`) и принятые изменения рабочего места: функциональный обзор (`1e894ad`), общие селекты Base UI (`3aded9c`) и закрытие оставшихся UI-критериев (`47b05f8`).

## Состав выпуска

- **Проекты и доступ.** Проверки project scope на HTTP/MCP, агентских назначениях, источниках, receipts и потоках обновлений; учёт человеческих аккаунтов, членства, приглашений и восстановления доступа. Этот код включает миграции 007–009 и не является только визуальным обновлением beta.2.
- **Рабочее место.** Отдельные разделы дорожной карты, спеки, вопросов, агентов, предложений и истории; раздельные диалоги подключения, назначения, решения и приёмки. Сведения и полные идентификаторы доступны для копирования, формы сохраняют введённые данные при внутренних переходах и SSE.
- **Достоверные состояния.** Независимые оси спеки, попытки и приёмки; результат агента не подменяет человеческое принятие DoD. Ревизия, попытка и история выбираются в согласованной области. План Flow отделён от фактического графа событий; причинные стрелки основаны только на сохранённых ссылках.
- **Общий выбор значений.** Установлен `@base-ui/react` 1.9.0. Все селекты приложения используют общий компонент; длинные списки поддерживают поиск, очистку и отсутствие совпадений. Пустой или полностью недоступный набор объясняется пользователю. Сохранены строковые значения, required, disabled, клавиатура, работа внутри dialog и черновики при обновлении вариантов.
- **Оставшиеся критерии обзора.** Запросы сгруппированы по виду и состоянию; раскрытия используют общий WorkspaceAccordion с клавиатурой и reduced-motion. Карточки графа показывают фактическое время обновления и связанные предложения. У спеки есть предложения выбранной ревизии/попытки; рассмотрение открывается в существующей полной карточке. Краткая история выводит сохранённые типизированные причину и результат, сохраняя полный источник в подробностях.
- **Знак Ouro.** Сохранены принятый вектор и движение по замкнутой S-траектории при hover/focus с учётом reduced-motion.

Подробности и доказательства: [функциональный обзор](../plans/functional-status-comments.md), [Base UI](../plans/base-ui-selects.md), [закрытие оставшихся критериев](../plans/review-followups.md).

## Обновление и сохранение данных

Перед первым запуском новой версии остановите прежний сервер и сделайте полную копию **остановленного** каталога PGlite `.ouro/postgres` либо соответствующую резервную копию фактически используемой внешней БД. Отдельно сохраните файлы ключей агентов и прежние настройки подключения. Ключи не входят в архив и не выдаются повторно из списка регистраций.

Новая папка установки сама не подхватывает прежнюю историю. Укажите прежний абсолютный `OURO_DATA_DIR` либо перенесите целиком остановленную базу. Не объединяйте каталоги разных баз и не запускайте два процесса с одним PGlite-каталогом. При заданном `DATABASE_URL` используется внешняя БД, а не `OURO_DATA_DIR`.

Относительно опубликованной beta.2 добавлены:

- `007_identity.sql` — аккаунты, password credentials, сессии и отзывы аккаунтов.
- `008_projects_memberships.sql` — metadata проектов, членство, приглашения, восстановления и назначения агентов; выполняется заполнение добавленных metadata.
- `009_membership_regrants.sql` — проекция действующего членства и повторные вступления. При первом применении записывается отзыв старых неиспользованных приглашений, предшествующих соответствующему отзыву членства; добавляются triggers и снимается прежнее ограничение уникальности пары проект/участник.

Миграции выполняются автоматически при инициализации хранилища. Поэтому открытие новой версии на рабочей базе требует резервной копии заранее. Простая замена приложения старой beta.2 не объявляется проверенным downgrade после 007–009: автоматических down-migrations нет.

Для выполненного обновления резервная копия остановленной БД проверена восстановлением. На отдельной копии число применённых миграций выросло с 6 до 9, число таблиц — с 25 до 41. После переключения рабочая установка использует прежнюю базу: сохранены 3 проекта, 238 событий и 2 регистрации; полные fingerprints исходных данных совпали, различий нет. Перерыв работы составил 14,402 с. Проверка копии и рабочей установки описана в [журнале поставки](../plans/release-beta-3.md).

Для восстановления остановите новую установку и сохраните её состояние отдельно. Возврат к прежнему коду с прежней резервной копией допустим, когда подтверждено отсутствие нужных новых записей после обновления. Если новые записи уже появились, восстановление старой копии потеряет их; нужен отдельный план восстановления с сохранением этих данных. Рабочие каталоги проектов и внешние keyfiles также должны оставаться доступными по сохранённым путям.

Общий способ запуска остаётся `npm run launch` с Node.js 24 LTS и npm; команда устанавливает зависимости, собирает приложение и запускает локальный сервер. Проверенный CI runtime закреплён в `.nvmrc`. [Инструкция установки](../first-release-guide.md) описывает базовый запуск и перенос; дополнительные требования миграции beta.3 приведены выше.

## Совместимость и границы

Переносимый протокол остаётся **`@ouro/protocol@0.1.2`**, **18 tools / 49 canonical JSON Schema**. UI-пакеты не переписывают канонические lifecycle-значения, события и исходную историю. Изменения хранения и авторизации 007–009 перечислены отдельно: неизменность версии MCP-протокола не означает отсутствие миграций БД.

[Предложение по статусным контрактам](../proposals/status-contract-followups.md) остаётся **proposal-only**. Новый обязательный порядок применения перед resume, самостоятельная проектная цель предложения, сохраняемый тип MCP-клиента, desktop-выбор пути и дополнительные event payload этим выпуском не реализуются и не активируются. Сохраняются действующие engine guards и раздельные человеческое решение, применение, разрешение продолжения, ACK и приёмка DoD.

Публичный GitHub prerelease распространяет локальное приложение; сам по себе он не создаёт размещённый веб-сервис. Настройка пользовательских MCP-клиентов и аккаунтов моделей остаётся отдельной проверкой.
