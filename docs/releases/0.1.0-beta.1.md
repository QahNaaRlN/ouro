# Ouro v0.1.0-beta.1

Первый beta-выпуск для локальной работы с агентами. Он объединяет принятый прототип в устанавливаемую версию с архивом, manifest/checksums и одним стартовым действием.

## Начать работу

На [странице выпуска](https://github.com/QahNaaRlN/ouro/releases/tag/v0.1.0-beta.1) выберите [ouro-0.1.0-beta.1-source.zip](https://github.com/QahNaaRlN/ouro/releases/download/v0.1.0-beta.1/ouro-0.1.0-beta.1-source.zip), распакуйте его и выполните в папке с `package.json`:

```sh
npm run launch
```

Нужен Node.js 24 LTS с npm. Git, Docker и внешний PostgreSQL для этого пути не требуются. Команда устанавливает зависимости, собирает production-версию и запускает Ouro. После `Ready` откройте `http://127.0.0.1:3000/projects` на том же компьютере и оставьте терминал открытым. [Полная инструкция](../first-release-guide.md).

## Возможности

- Любая существующая папка как отдельный проект, без обязательного Git.
- Единый realtime-дашборд с roadmap, подробным Flow, агентами и назначениями, человеческими запросами и подтверждёнными событиями.
- Cursor, Claude Code и Claude Desktop через общий MCP stdio bridge; отдельные регистрации и файлы ключей, точный project URL и готовый JSON. Для ChatGPT сохранён пример Secure MCP Tunnel.
- Явные человеческие решения и приёмка: назначение, ACK, применение, результат и DoD остаются разными фактами.
- Строгие последовательные проходы Flow, сохранение прежних посещений/оснований, human retry/skip и guards переходов.
- Source-backed предложения агента с человеческим рассмотрением, созданием черновика и отдельной активацией.
- Сохранение истории в локальном PostgreSQL/PGlite, project isolation, immutable revisions, exact retries и SSE recovery.
- Прежний Human View с GitHub evidence, уроками/происхождением, показателем дрейфа, совместными черновиками и импортом контекста Meridian.

## Артефакты и протокол

Подготовленный набор: исходный ZIP, `ouro-protocol-0.1.2.tgz`, `release-manifest.json` и `SHA256SUMS`. Manifest содержит точный source commit и контрольные суммы. Для установки самого приложения отдельный tarball протокола не требуется.

Протокол сохраняет версию `0.1.2`,18 tools и 49 canonical JSON Schema; он работает отдельно от Next.js и базы. Выпуск на GitHub не является публикацией пакета в npm registry.

## Репозиторий

`main` предназначена для принятых релизов, `dev` — для интеграции следующей версии. Английские имена веток, Conventional Commits и правила SDD/TDD описаны в [CONTRIBUTING](../../CONTRIBUTING.md). Общая история и существующие feature branches сохраняются. Фактическое состояние ветки по умолчанию и результаты публикации фиксируются в [журнале релиза](../plans/first-release.md).

## Проверки и границы

Локально прошли368/368 unit/integration и71/71 production E2E, сборка, TypeScript и независимая установка протокола1/1. Чистый ZIP проверен без Git в пути с пробелами, кириллицей и апострофом, при NODE_ENV=production: установка, build/start, настоящий MCP и сохранение точной истории после полного повторного launch. Реальные GitHub jobs checks/browser зелёные для функционального кандидата; публикация требует тех же проверок финального PR head. [Подробности](../plans/first-release.md), [CI](https://github.com/QahNaaRlN/ouro/actions).

Проверенная среда — Linux/Node 24. Native Windows/macOS/WSL и пользовательские GUI/аккаунты Cursor/Claude Desktop отдельно не объявляются принятыми. Реальный Claude Code MCP health-check без LLM и SDK-проверки готовых профилей сохранены в предыдущей приёмке.

Это локальная beta с доверенным оператором, а не облачная tenancy-платформа. Ouro не запускает модель автоматически и не перехватывает все действия IDE. Его файловые инструменты дают read-only контекст; нативные edit/shell инструменты Cursor/Claude Code принадлежат самим клиентам. Перед обновлением сохраните существующую базу и внешние key files по [инструкции переноса](../first-release-guide.md#обновить-установку-и-сохранить-данные).
