# Уточнения, исправления и восстановление

## Решения с сохранением истории

В карточке открытого запроса человек может запросить уточнение. Агент получает отдельный факт и отвечает через `ouro.submit_decision_clarification`, ссылаясь на его event ID. Исходный текст и варианты остаются прежними; ответ на уточнение не выдаёт разрешение продолжать.

До применения решения человек может открыть исправление с причиной. Появляется новый связанный запрос с теми же вариантами, требующий нового ответа/выбора. Прежний outcome остаётся в истории. Прежнее разрешение продолжения сбрасывается; применение старого решения и выдача remediation по нему запрещены. После применения, результата, приёмки либо уже выданной remediation нужно оформить новую ревизию/спеку.

Автор-агент может отозвать свой открытый запрос через `ouro.withdraw_decision`. Исполнение не возобновляется автоматически. У отозванного Blocker остаётся физическое препятствие: человек явно возвращает план на рассмотрение, затем согласует его и отдельно получает успешную remediation с evidence. Новая ревизия сама по себе также не снимает старый физический барьер.

Если контракт изменился, человек после остановки и завершения всех попыток может записать основание неприменимости исторического Blocker к выбранной активной ревизии. Это пересмотр области применимости, а не свидетельство физического устранения. При выборе другой ревизии, включая возврат к прежнему контракту, барьер снова требует проверки. Для вернувшегося контракта можно открыть новый план и отдельную remediation, сохранив старую основную попытку завершённой.

## Состояние на выбранном cursor

В «Истории» укажите зафиксированный cursor и откройте исторический просмотр. Снимок содержит только подтверждённый префикс событий: 0 означает состояние до первого события. Ожидания, решения, статусы и диаграммы соответствуют именно этой точке. Формы изменения и вложенные панели записи в этом режиме не открываются.

Live-соединение продолжает принимать события; выбранный снимок остаётся закреплённым. Баннер показывает историческую и последнюю версии. Вернуться к работе можно явной кнопкой. Экспорт исторического снимка включает выбранный cursor и его префикс событий.

## Экстренно отозванный агент

1. Отзыв ключа прекращает доступ к Ouro. Внешний процесс он физически не останавливает.
2. В исполнении выберите операторскую отмену, укажите причину и основание. Сервер проверяет реальный отзыв именно назначенного агента в реестре. Состояние разрешения становится «Отменено», рядом остаётся «Фактическая остановка не подтверждена».
3. Проверьте внешний процесс и рабочую область. Отдельно запишите свидетельство фактической остановки с evidence. Автором этого свидетельства показан оператор; агентский ACK не создаётся.
4. После этой записи можно отдельно назначить новую попытку. Открытые Blocker, зависимости, ревизия и приёмка DoD по-прежнему проверяются. Ни операторская отмена, ни свидетельство остановки не создают новую попытку и не принимают DoD.

Неизвестная фактическая остановка запрещает новое конфликтующее исполнение и архивацию roadmap независимо от терминального статуса отменённой попытки. Повтор команды с тем же requestId возвращает прежний receipt; история и evidence сохраняются после перезапуска.

## Принятые ориентиры

[W3C SCXML](https://www.w3.org/TR/scxml/) задаёт полезный принцип отдельных автоматов и guarded transitions. [Fowler: Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html) объясняет воспроизводимые проекции и новые компенсирующие факты вместо изменения прошлого. Ouro использует один авторитетный reducer для текущего состояния, исторического cursor и реальных переходов. Посетитель replay собирает переходы за один проход вместо многократного пересоздания всех префиксов. SCXML-интерпретатор и управление внешним процессом не заявляются.
