# Остатки комментариев №13, 17, 19, 21 и 22

03.11.2026. Продолжение принятого интерфейса `3aded9c`. Пользователь поручил закрыть оставшиеся UI-критерии, а изменения статусной модели и контрактов предварительно описать отдельно.

## Граница реализации

Используются установленные React19, Next16, Base UI1.9, React Flow, Dagre и общий WorkspaceAccordion. Не меняются команды, lifecycle-значения, guards продолжения/приёмки, события, права, SQL и MCP-схемы. Проектные предложения без исходной спеки, client metadata и нативный выбор пути остаются только в [предложении для согласования](../proposals/status-contract-followups.md).

## Проверяемый результат

| Критерий | Поведение |
|---|---|
| RF13 | При 10 и более вариантах общий контрол предлагает текстовый поиск средствами Base UI. Выбор по клавиатуре, пустые значения, required, disabled, controlled callbacks и портал внутри native dialog сохранены. Различаются отсутствие вариантов, недоступность всех вариантов и отсутствие совпадений. Поиск не меняет выбранное значение и черновик формы. |
| RF17 | Актуальные запросы после совместного фильтра по spec/revision/execution сгруппированы по виду и состоянию. Pending показаны первыми внутри каждого вида, количества соответствуют видимым группам. Подробная карточка и отдельные стадии решения сохраняются. |
| RF19 | Остаточные native details заменены общим доступным анимированным аккордеоном, с сохранением начальной открытости и черновиков. Карточка графа показывает время реального последнего события либо честное отсутствие событий. Размещение и измерение React Flow учитывают высоту карточки. |
| RF21 | У спеки есть счётчик и ссылки на предложения выбранной ревизии/попытки, включая режим всех попыток. Карточка графа открывает предложения активной ревизии всех её попыток. Ссылки ведут к существующей полной карточке; формы рассмотрения не дублируются. Чужой или неизвестный scope не подменяется подходящим предложением. |
| RF22 | Краткая история показывает уже сохранённые типизированные reason/outcome. Длинные значения ограничены визуально; полная неизменённая запись доступна в подробностях. Из evidence новые причина/результат не выводятся. |

## Проверки

Целевые unit и production browser-сценарии должны проверить поиск/пустоту, группы и scope, timestamp/disclosures, связанные предложения и неизменность истории. Затем typecheck, production build и регрессии затронутых старых экранов. Все записи тестов выполняются только на новых временных проектах и БД. Результаты фиксируются в [плане проверок](../plans/review-followups.md), без подмены локального gate результатами CI или релиза.
