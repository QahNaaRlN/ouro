# OURO-ENG-000002 · Процессные схемы и графы состояний

Редакция 1 · 29.10.2026 · SDD до реализации. Следующий совместимый пакет alpha.3 поверх alpha.2. Пользователь продолжает тестировать alpha.2; её сервер, каталог БД и рабочая копия изолированы от разработки.

## Контракт

`SpecRevision.flow?` содержит `FlowDefinition {entryNodeId,nodes,edges}`. Узел: `{id,kind,title,description,owner}`, kind=`action|condition|question|fork|blocker|wait|result`, owner=`human|agent|system`. Ребро: `{id,source,target,label,optionId?}`. ID стабильны в пределах схемы, координаты — только состояние представления. Отсутствующее flow не нормализуется в сохранённых старых snapshots.

Flow — возможный процесс, не workflow-runner и не авторизация. Циклы с выходом допустимы; DAG Roadmap остаётся отдельной моделью. Проверяются границы 1–100 nodes/0–200 edges, уникальность ID, типы/непустые title, существование entry/концов, отсутствие дубликата source/target/label, достижимость всех узлов от entry и возможность добраться из каждого до result. Result не имеет выходов. У condition/fork минимум два различимых подписанных исхода. Непустой optionId уникален среди исходов одного Fork: исключающий выбор не обозначает два пути. Question/fork принадлежат human, выбор никогда не автоматический. Нельзя сохранять произвольные/неизвестные поля Flow.

Сохранение схемы создаёт `proposeRevision` полного snapshot; активация отдельно. Просмотр предыдущих ревизий read-only. Редактор предоставляет граф, таблицу и формы создания/изменения/удаления узлов и связей без обязательного drag. Ошибка сохраняет локальный draft. Новые события не сбрасывают несохранённый draft, выбор и камеру. Внешнее изменение базовой ревизии запрещает молча перезаписать её.

Report tools и команды получают optional `flowNodeId`. Сервер проверяет узел в назначенной execution ревизии, а не в последней активной: Action допускается для action/condition/wait/result; Question/Fork/Blocker — для одноимённого kind. Ссылка фаз одного actionId неизменна. При отсутствии ссылки факты остаются без привязки, а не угадываются. Поздний Action старой ревизии сохраняет её ссылку. Ни посещение result, ни успешный Action не принимают DoD. Выбранный путь Fork выделяется только при явном совпадении edge.optionId с решением и подтверждении его применения; неподтверждённый выбор обозначается отдельно.

Статусная диаграмма — отдельное представление автомата Roadmap/Spec/Execution/DecisionRequest с текущим подтверждённым состоянием, возможными переходами и объяснением guard/author. Произошедшие переходы выводятся из действительных событий/проекций; разрешение и ACK показаны отдельно, без выдуманного автоматического перехода. Выбор узла ничего не исполняет. Старые Mermaid-документы сохраняют роль справки.

Оба графа используют существующие семантические токены Meridian, светлую/тёмную темы, текстовые статусы, подписи исходов и reduced-motion. Нет BPMN-совместимости или нового LLM runner.

## Приёмка

| ID | Наблюдаемое поведение | Проверка |
|---|---|---|
| F01 | Legacy-ревизии без flow читаются без изменения hash | storage regression |
| F02 | Валидная схема, включая цикл с выходом, сохраняется/replay/reopen | core + SQL |
| F03 | Неверные ID/kinds/концы, тупик, недостижимый узел, неразличимый выбор отвергаются без записи | domain tests |
| F04 | Изменение r2 не меняет r1, activation отдельно | domain + browser |
| F05 | MCP публикует optional ссылку; чужая/неверного типа ссылка и смена actionId-привязки отвергаются | facade + SDK |
| F06 | Late Action связан с прежней immutable схемой, результат не принимает DoD | domain |
| F07 | Редактор работает формами без drag; draft не пропадает при polling; старая схема read-only | browser |
| F08 | План/выбор/применение и непривязанные факты различимы, связи не угадываются | projection + browser |
| F09 | Графы всех четырёх статусных осей показывают текущее состояние и объясняют переходы, ACK отдельно | projection + browser |
| F10 | Светлая тема, длинные подписи, reduced motion и регрессии alpha.2 | browser + test/typecheck/build |
