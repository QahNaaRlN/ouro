# OURO-ENG-000012 · переход от дорожной карты к процессу спеки

29.10.2026 · SDD до исправления. Пользователь сообщил: клик по спеке в дорожной карте не открывает подробную блок-схему.

## Воспроизведённая причина

Граф передаёт клик в `pick`, который только выбирает ID. Таблица открывает карточку, сохраняя прежнюю вкладку (`expectation` по умолчанию). Проверки схем ранее открывали «Спецификации → Процесс» вручную и не проверяли этот вход. Enter в React Flow не вызывает пользовательский `onNodeClick`. Шесть исходных seed-спек не содержат `flow`.

## Критерии приёмки

1. Один клик по карточке графа и кнопка спеки в таблице открывают **«Спецификации → Процесс»** для точного выбранного ID. Явная кнопка открытия процесса ведёт туда же.
2. Открывается активная ревизия, соответствующая исполнению; при отсутствии активной — последняя предложенная. Прежний выбор вкладки/ревизии другой или той же спеки не подменяет этот вход. Другую ревизию можно выбрать явно.
3. Enter и пробел на фокусируемой карточке графа открывают тот же процесс. Стрелки, перетаскивание и pan не запускают переход; обработчик не перехватывает клавиши контролов холста.
4. Если в выбранной ревизии нет `flow`, показано понятное пустое состояние с номером ревизии и существующим явным действием создания. Схема не выдумывается и не записывается при открытии.
5. Навигация сохраняет выбранную спеку и фильтры при возвращении на дорожную карту. Она не меняет domain cursor, active revision, выполнение или DoD.
6. Историческая read-only панель не затрагивается; старые immutable ревизии и пользовательские БД не переписываются. Автоматическое заполнение существующих спек и сохранение viewport между страницами не входят в этот fix.

Основание: существующая [методология графов](../diagram-methodology.md), [инструкция процесса](../flow-guide.md), установленная Next.js 16.4.3 документация Client Components/event handlers и фактически прочитанный NodeWrapper `@xyflow/react`. Визуальная схема плана и подтверждённые факты исполнения остаются раздельными.
