## Immutable contracts and evidence

The optional `RevisionContent.verification` specializes an ordinary Spec. The first immutable revision determines its stable role; later revisions cannot add/remove this discriminator. Absence means work. Historical JSON and hashes are never padded with defaults. Binding is one exact work revision in the same project, with criterion IDs and logical cases. A proposal ID cannot bind. Activation remains human admission; assignment is separate. Changing a verification expectation requires a reason in the revision comment and explicit activation. Case/expected/required/procedure/binding diffs remain visible.

Logical cases retain given/action/expected, prerequisites/data, level, purpose, required status and explicit execution linkage. Mutation quality is an optional independent axis: policy declares a required score from 0 to 100; evidence records killed, survived, no-coverage and timed-out counts. Mutation quality never replaces functional outcomes or human acceptance. A separate mutation execution adapter is outside this bounded package.

Runs, run reviews, declared or observed current slices, phase records, cycles and refactor admissions are separate immutable events. Runs are also indexed in an append-only table through migration 010. Replay is authoritative. A FlowStepRun is an optional reference to a started execution occurrence, never a test run. Current slices pin product, test, fixture and environment inputs. Missing inputs mean unknown; a mismatching slice means stale. Selecting a historical run does not set the current slice.

The aggregate chooses the most recent evidence per logical case across partial runs and exposes its exact run ID, outcome, applicability and admission reason. A later skip, error, unreviewed result or stale attempt revokes an earlier PASS; an older successful run cannot silently reappear. Every required case must have admitted applicable functional evidence, and any required mutation policy must also pass. An optional skip remains visible. An unlinked case cannot qualify. A verified subset never implies complete contract coverage.

## Provenance, observation and the bounded adapter

The Playwright built-in JSON importer parses explicit test IDs, outcomes and runner errors, rejects duplicate IDs/contradictory totals, and retains the original text with a server-computed SHA-256. It rejects ambiguous retries/flakiness rather than accepting them as GREEN. Imports never execute commands or fetch artifact URLs. Their `imported_report` source establishes the ingested bytes; declared paths/revisions/environment and artifact references are not runner attestation. Imported evidence requires a separate human assessment and prerequisite evidence before readiness.

A human can record a manual procedure result with actual outcome and evidence. Only cases linked to manual procedures are accepted through this action; the run remains bound to a running assigned verification execution and immutable revisions. Its `human_attested` provenance is distinct from process-observed evidence and still requires a separate human run assessment before readiness.

A human admits observation configuration for 1–32 explicit product/test/fixture/config files within the anchored project workspace, the included Playwright configuration path and optional required capability values. The server observes exact file hashes/sizes/roles and measured runner capabilities, records their manifest/digest, and derives the current slice. Changed inputs update applicability without rewriting earlier runs. Unavailable files/capabilities or a new configuration without a matching observation produce unknown. Observations are written by the server observer or an explicit human action, never as a side effect of a read-only GET.

Observation is deliberately bounded to the admitted file list and capabilities. It does not discover all transitive dependencies, external services, ambient conditions or unlisted files. An artifact manifest describes exactly this measured scope. Qualification must preserve that boundary rather than treating its digest as proof of every possible input.

The same Playwright adapter also has a fixed server-owned execution path. It accepts an assigned execution and case scope, not arbitrary binaries, shell commands, environment variables or argv. It runs copies of the exact observed file bytes through the installed Playwright CLI with one configuration, one worker and no retries; before/after observations, raw report/hash, runner version, exit code and input stability are retained as `local_runner` provenance. Applicable successful evidence with a matching manifest, stable inputs and successful process exit may qualify as functional GREEN without an additional import review. Expected RED and preservation baseline still require human semantic assessment. Runner errors, timeouts, skips and ambiguous attempts cannot supply substantive RED.

The child process runs outside the project transaction/lock so stop and authority changes remain possible. Migration 011 stores durable operational request reservations and exact results. A pending/unknown request is not rerun automatically; a changed body cannot reuse its request ID. Only the internal service proof can record a late observed result after stop, terminal state, activation change or Flow advancement. That immutable fact retains its original execution/revisions and started Flow occurrence; it does not resume work, advance a Flow or grant readiness against a different active binding.

## TDD, preservation and human authority

TDD compares exact contract/scope/test/fixture/environment snapshots; product revisions may differ between RED and GREEN. Implementation readiness is qualified RED for that revision/scope, or qualified baseline for preservation. It is not a reciprocal `depends_on`. Expected RED requires an observed functional failure, working prerequisites and human classification. Reviews can be superseded by later immutable reviews; invalid or unresolved evidence never gains admission automatically.

Persistent cycles retain exact revision/scope, admitted RED/baseline run IDs, exact GREEN run IDs and immutable transition history. Human begin creates preparation. Ordered transitions are preparation → implementation → verification; verification may enter refactoring or acceptance; refactoring returns to verification. Human cancellation is explicit. Implementation and refactoring require actually running bound primary work, verification requires running/succeeded bound work, and cycle acceptance requires succeeded work plus applicable scoped evidence. GREEN references must be the latest admitted per-case evidence and must have been recorded after the relevant verification entry, so pre-refactor GREEN cannot close the refactor round.

A human may admit a test refactor with exact from/to slices, scope, reason and evidence. This permits comparison of an older qualified RED/baseline for the admitted cases while keeping fixture/environment fixed; it never transfers an earlier PASS to changed tests. Assertion equivalence is a human claim with visible evidence, not an automatic proof. A subsequent review may revoke the source evidence.

Phase facts and cycles do not authorize an execution. Begin/cancel/refactor admission remain human actions. Assigned verification agents may report permitted non-cancel cycle transitions only for their running execution through the existing authority guards. All assignment, stop/resume, CAS, exact-request receipt and human acceptance boundaries remain. Cycle acceptance and GREEN do not accept a work Spec or its DoD.

## Presentation and portable protocol

Graph/list/details use one pair projection. Multiple verification specs of one work are deterministic separate layers in one work group. Group ID is the work Spec ID; both identities/revisions remain navigable. Actual refactoring is a separate displayed phase. Local foreground override does not write a command. History uses the supplied event prefix and never live data.

The card has work and verification faces with a vertical-axis flip. Both faces and the navigation footer reserve the same geometry. Side controls stay outside the rotating surface; keyboard focus is preserved, and the inactive face is inert/aria-hidden. `prefers-reduced-motion` switches instantly. The owner-requested slower transition is 700 ms, and header links have no underline, including hover. Flipping remains local view state.

Protocol 0.3.0 publishes 20 tools and 71 canonical schemas, including typed cycles, observation, manual evidence, quality and runtime inputs. Existing tool arguments remain valid; omitted negotiation selects the current contract. Explicit 0.1.2/0.2.0 context requests advertise no verification capabilities and support only authorized visible work/proposals without verification data. Assigned verification or a visible verification proposal fails closed with an upgrade requirement; evidence is never dropped to fit an old schema. Unrelated assignments/projects do not block a selected ordinary context. Unsupported versions/capabilities are rejected. Negotiation does not downgrade other tools or teach an old replay client new events: unknown events are rejected, never silently ignored. Historical events, revision hashes and saved receipts remain unchanged.

The canonical portable packing route normalizes actual tar entry modes to 0755 for directories/CLI and 0644 for ordinary files, then recalculates checksums and archive integrity. This addresses the original Windows packaging defect. It does not by itself establish Linux/Unix runtime qualification or equivalence with an arbitrary raw `npm pack` invocation.

## Qualification and exclusions

Evidence must cover domain/replay/hash/authority guards, aggregate latest-result revocation, cycle ordering and fresh exact GREEN links, scoped refactor admission, manual and mutation semantics, adapter errors and actual Playwright processes, observer drift/unavailability, late historical facts, storage rollback/idempotency/reopen, protocol generated consistency, canonical package modes, Yjs round-trip, shared pair projection and browser authoring/import/run/flip paths on isolated data. Actual results are recorded in [the qualification report](../verification-validation.md). Earlier MVP checks are historical evidence for their own scope; this specification does not claim an unrun browser or full-suite success.

M:N binding, a universal CI system, a separate mutation runner, live Concord and the native Meridian host remain outside the original bounded package. Owner acceptance and release remain separate.
