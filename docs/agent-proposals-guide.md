# Сводки Reality и предложения новой спеки

Пакет OURO-ENG-000009 · [SDD](specs/agent-proposals.md) · [реальные проверки](plans/agent-proposals.md).

## Подключённому агенту

1. Прочитайте `ouro.get_context` выбранного `executionId`: неизменяемую ревизию, разрешения и `proposalSourceIds`.
2. Через `ouro.get_updates` получите первичные committed события. Общий cursor может проходить через скрытые события; это не разрешает ссылаться на чужой контекст.
3. Вызовите `ouro.submit_proposal` с executionId, requestId, expectedVersion, sourceCursor и content. `reality_summary` содержит title, findings[{text,sourceEventIds}], interpretation, limitations. `spec_proposal` также содержит draft с обычными полями ревизии и DoD; Flow необязателен.
4. Каждое наблюдение должно ссылаться на точные IDs доступных событий этого исполнения. Нужен реальный observation/lifecycle/decision факт; одно разрешение запуска не доказывает исполнение. Источник из другой попытки, даже назначенной тому же агенту, недопустим.
5. Для уточнения pending предложения передайте оба proposalId/baseProposalRevisionId. Сохраняйте requestId и тело при сетевом повторе. После VERSION_CONFLICT перечитайте контекст и явно сформируйте новую команду.

Схема закрыта: автор/проект/ревизия/состояние review/публикация не принимаются из агентского payload. Сервер выводит их из назначения. Можно предложить исторический анализr1 после активацииr2; это не разрешает возобновлятьr1.

## Человеку

Откройте «Предложения агента», выберите предложение и раскройте цитаты. Здесь видны исходный автор, Spec/rN/execution, sourceCursor, интерпретация и ограничения. Предыдущие версии доступны для чтения; новая версия не переписывает введённую форму.

Сводку можно отметить рассмотренной или отклонить. Для предложения спеки отредактируйте цель, DoD и остальные поля, оставьте комментарий агенту и создайте черновик. Схема процесса сохраняется; её редактор доступен в созданной спеке. Явная связь происхождения с исходной спекой добавляется только по выбору человека.

«Комментарий агенту» виден агенту в исходном исполнении. Поля новой спеки, включая «Комментарий к спеке», принадлежат новой неназначенной спеке и через старое назначение агенту не раскрываются. Принадлежность цитат проверена, смысл вывода требует вашего рассмотрения.

При появлении новой версии сначала прочитайте её, затем явно обновите основу, сохранив собственный текст. При неопределённом результате записи форма сохраняет исходное тело/requestId и предлагает повтор. Это выясняет уже совершённый эффект и не создаёт второй черновик. Ответы аутентификации или ограничения частоты не подтверждают отсутствие записи и не снимают блокировку неопределённого результата. Если receipt-aware проверка подтвердила отсутствие записи, конфликт версии разрешает осмысленно обновить основу. Незавершённый запрос сохраняется в памяти текущей страницы при переходах между разделами; сохранение через полную перезагрузку или закрытие вкладки не обещается.

Результат adoption — idea Spec с точной ссылкой на immutable версию предложения. Активация, разрешение попытки, человеческая приёмка DoD и публикация Lesson выполняются отдельно.

Встроенный model runner не добавлен. Текст присылает настоящий внешний MCP-клиент/агент; автоматическое качество всех LLM и истинность интерпретации не заявляются. Протокольные fixtures явно обозначены тестовыми и не выдаются за результат модели.

Ориентиры: [официальный MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) для схем и протокольных границ; [W3C PROV-DM](https://www.w3.org/TR/prov-dm/) для различения источника, версии и ответственности автора. Конкретное применение и границы чтения — в [журнале](plans/agent-proposals.md).
