Вход — <http://127.0.0.1:3000/projects>. Выберите папку на машине, где работает Ouro, и откройте рабочее место. В навигации проекта доступны **«Дорожная карта»**, **«Вопросы»**, **«Агенты»**, **«Предложения»** и **«История»**. Выбор спеки открывает её подробности с ревизиями и попытками. Любой совместимый агент сообщает данные через общий версионированный MCP-контракт. ChatGPT — пример подключения; запуск модели остаётся в клиенте агента.

Этот адрес работает после локального запуска по [README](../README.md), на том же компьютере, где открыт браузер. `127.0.0.1` из облачной среды разработки не является доступной извне ссылкой. Используйте порт из строки `Local` своего запущенного терминала; ошибка соединения и отсутствие `Ready` означают, что локальный запуск ещё нужно проверить.

Выбор папки, регистрация и назначение задачи — вход в этот дашборд. Основной результат — наблюдаемая работа проекта и решения человека, а не последовательность настроек или пакет файловых изменений.

## Добавить папку

1. Запустите репозиторий по [README](../README.md) и откройте **«Проекты»**.
2. Заполните **«Папка проекта»** абсолютным путём к существующей папке. **«Выбрать папку»** открывает просмотр папок на сервере Ouro; это не загрузка файлов из браузера. Можно перейти по подпапкам и нажать **«Выбрать эту папку»**. Если сервер работает на другой машине, нужен путь именно на ней.
3. При желании задайте **«Название проекта»** и нажмите **«Добавить проект»**.
4. Откроется `/projects/{projectId}` с сохранённой привязкой и собственной историей. Git для этого не нужен. Файлы и зависимости выбранной папки не изменяются.

Другой путь, который после realpath указывает на ту же папку, возвращает существующую запись. Привязка к корню фиксируется при добавлении. Исчезнувшая или подменённая папка не подставляется заново: новые запуски и файловое чтение получают ошибку привязки. Верните исходную папку или добавьте другой проект; тихой смены root у прежней истории нет.

Новый проект начинает с пустой карты и без учебных задач. **Demo** в каталоге сохраняет прежний проект, его историю и полный Human View; у него нет файловой папки. Старый интерфейс по `/` также остаётся доступен. Новая компактная поверхность пока не переносит все legacy-интеграции и панели в несколько проектов.

## Зарегистрировать подключение

1. Откройте раздел **«Агенты»** и нажмите **«Подключить агента»**. В отдельном диалоге выберите профиль клиента и нажмите **«Зарегистрировать агента»**. Имя формируется из клиента и проекта; повторные регистрации различаются суффиксом. Права определяет созданная регистрация, а не название клиента.
2. Сохраните **«Ключ агента»** в отдельный локальный файл вне репозитория и папки контекста. Поле показывается один раз. На macOS/Linux ограничьте файл правами своего пользователя, например `chmod 600 /absolute/path/ouro-agent.key`; на Windows ограничьте доступ к файлу своей учётной записью.
3. Укажите абсолютный путь в **«Файл ключа агента»**. Скопированная или скачанная **«Конфигурация MCP»** содержит этот путь и project-specific OURO_URL, без значения ключа. Конфигурацию можно получить повторно после скрытия одноразового ключа; существующие настройки клиента объединяются вручную без потери других подключений.
4. Добавьте готовый JSON по [инструкции Cursor/Claude](agent-clients-guide.md) и включите сервер/разрешения в клиенте. Эти локальные stdio-профили обходятся без Tunnel. Для других совместимых клиентов есть [общая инструкция](agent-quickstart.md), для ChatGPT — отдельный [пример Secure MCP Tunnel](chatgpt-guide.md).

Регистрация создаёт ключ и привязку подключения в Ouro. Существующие регистрации, назначения и отзыв ключа находятся в разделе **«Агенты»**. Настройка клиента выполняется отдельно; у ChatGPT — в своём аккаунте OpenAI. **«Последнее обращение»** означает наблюдавшийся вызов, а не постоянно работающий канал или начатую задачу. Тип клиента не угадывается по имени; при отсутствии достоверных metadata показывается неизвестный тип. Абсолютный путь к файлу ключа вводится вручную: браузерный выбор файла не раскрывает такой путь.

Каждый проект имеет свой MCP endpoint и регистрацию. Переключение браузера на проект B не меняет подключение агента к A. Для другой папки создайте отдельное подключение; не добавляйте projectId в tool arguments.

## Назначить задачу

1. Нажмите **«Назначить работу»** в шапке проекта. В отдельном диалоге выберите **«Исполнитель задачи»** из активных регистраций этого проекта.
2. Введите **«Задача для агента»**. Первая строка предварительно заполняет **«Название задачи»**, его можно исправить.
3. Заполните **«Критерии готовности»**: по одному проверяемому критерию на строку. Перед запуском они видны в отдельном списке; нужен хотя бы один.
4. Нажмите **«Назначить работу»**. Одна команда создаёт спеку, активирует точную ревизию и назначает одну queued-попытку; откроются подробности созданной спеки.
5. В **«Управление попыткой»** откройте **«Инструкция назначенному агенту»**, скопируйте полную инструкцию и передайте её подключённому клиенту. Для ChatGPT выберите нужный plugin в разговоре и попросите прочитать `ouro.get_context`, затем подтвердить начало через `ouro.confirm_started`.

**«Ожидает агента»** остаётся до настоящего MCP ACK. Нажатие кнопки само не запускает модель в фоне. Назначение этой задачи не означает согласования подробного плана или приёмки DoD. Если задача требует изменения файлов, а у клиента есть только инструменты Ouro, агент должен обозначить ограничение: файловые tools этого пакета дают чтение, без write/shell.

В длинном списке исполнителей Base UI показывает поле поиска; в коротком — обычный раскрываемый выбор Base UI. Поиск фильтрует варианты, Enter выбирает, Escape закрывает список. Пустой или полностью недоступный набор сопровождается объяснением. Поиск и смена раздела не отправляют форму; введённые значения сохраняются при обновлениях.

## Следить за работой и отвечать

В дорожной карте или списке выберите спеку. Дашборд сохраняет один выбранный project/spec/revision и согласованно показывает связанные представления:

| Область | Что читать |
|---|---|
| Шапка и сведения проекта | Состояние обновлений, путь и копирование полных ID; cursor подписан как позиция истории |
| Дорожная карта | Граф и список одной коллекции с общими поиском/фильтром; отдельные fullscreen и fit, время реального последнего события |
| Подробности спеки | Обзор цели/DoD, точные ревизия и попытка; отдельные вкладки «Процесс», «Вопросы», «Предложения», «История» |
| Процесс спеки | Раздельные «План» и «Фактическое исполнение»; факты видны без Flow, стрелки требуют сохранённых причинных связей |
| Агенты | Регистрации, назначения, queued/ACK, ключи и наблюдавшиеся обращения |
| Вопросы | Актуальные цепочки Question/Fork/Blocker по виду и состоянию; полный запрос открывается отдельно |
| История | Краткие типизированные записи с автором, временем и имеющимися причиной/результатом; полный исходник и evidence в подробностях |
| Предложения | Существующие предложения с источниками и версиями; у спеки — счётчик и ссылки выбранной ревизии/попытки |

Новые MCP-факты обновляют разделы через committed SSE без перезагрузки. Выбранная ревизия и попытка задают совместную область вопросов, истории и предложений; чужой или неизвестный ID не подменяется другой записью. Граф и список сохраняют выбор и пользовательский масштаб при обычных обновлениях. Новая задача не получает выдуманный процесс автоматически. Если событий нет, фактическое исполнение показывает пустое состояние; при отсутствии Flow факты остаются доступны.

В **«Предложения агентов»** назначенный агент может предложить новую спеку с Flow через `ouro.submit_proposal`. Прочитайте наблюдения, первичные события и ограничения, при необходимости измените поля ожидания, добавьте комментарий и нажмите **«Создать черновик спеки»**. Исходное предложение сохраняется. Черновик появляется на карте, но ещё не активирован и не исполняется. Откройте его, отдельно активируйте ревизию и в **«Назначить попытку по этому ожиданию»** выберите агента. Новое событие или новая версия предложения требуют обновить просмотренную основу; введённый вами текст сохраняется.

Вкладка **«Предложения»** у спеки показывает выбранную ревизию и попытку; вариант **«Все попытки ревизии»** расширяет только область этой ревизии. Кнопка предложений на графовом узле открывает активную ревизию со всеми её попытками. Ссылка ведёт в ту же полную карточку рассмотрения и сохраняет её неотправленный черновик. Самостоятельные предложения уровня проекта без нынешней привязки к исполнению не добавлены.

При наличии подходящего Flow можно явно включить **«Строгий учёт проходов»** для новой попытки. В **«Текущий проход процесса»** видны run/visit, владелец и доступность человеческих действий с причинами. Свои и наблюдаемые системные шаги человек подтверждает отдельно, агентские шаги приходят по MCP. Запуск/завершение/ошибка, человеческие retry/skip, причина и evidence подчиняются тем же серверным правилам, что и прежний Human View; одного клика по ребру недостаточно.

| Подпись в интерфейсе | Ось и подтверждённый смысл |
|---|---|
| Ожидает агента | Работа назначена; ACK начала ещё нет |
| Выполняется | Агент подтвердил начало или разрешённое продолжение |
| Ожидает человека | Есть человеческое ожидание по действующим guards |
| Приостановлено | Зафиксирована пауза; отдельное разрешение продолжения не является ACK |
| Результат предъявлен | Агент сообщил успех попытки с evidence; человек ещё проверяет DoD |
| Принято человеком | Приёмка спеки: человек отдельно подтвердил критерии; это не состояние попытки |

В **«Вопросы и решения»** откройте полный запрос, ответьте на Question либо выберите вариант Fork/план Blocker и нажмите **«Записать решение»**. Ответ, применение, разрешение продолжения и ACK показаны раздельно; одобрение плана Blocker не означает устранения препятствия. Доступность **«Разрешить продолжение»** определяется действующими guards. Текущая модель допускает resume после положительного решения до отдельного подтверждения применения, если остальные условия выполнены; у строгого шага собственные требования применения/clearance. Агент отдельно отправляет `ouro.confirm_resumed`. Более строгая последовательность только [предложена для согласования](proposals/status-contract-followups.md).

После предъявленного результата нажмите **«Проверить результат»** в подробностях спеки. В отдельном диалоге укажите своё подтверждение каждого обязательного критерия и нажмите **«Принять результат по DoD»**. Отчёт агента и человеческая приёмка сохраняются отдельно.

Прежняя [методология решений и восстановления](methodology-guide.md) и [строгие проходы](flow-runtime-guide.md) продолжают действовать. Компактный старт задачи не включает flowTracking автоматически и не создаёт обхода человеческих guards.

## Что агент читает из папки

`ouro.get_context` содержит workspace metadata и capability `readOnlyFiles:true`, если проект имеет файловую привязку. Абсолютный host root остаётся в человеческом интерфейсе. Файловые вызовы требуют настоящее назначение на переданный executionId этого проекта.

| Tool | Формат и ограничения |
|---|---|
| `ouro.list_workspace_files` | executionId, необязательные относительный path и cursor; одна папка, до 200 записей, nextCursor и truncated, без рекурсивного сканирования |
| `ouro.read_workspace_file` | executionId и относительный path; текст UTF-8 до 128 KiB, sha256, size и modifiedAt |

Используйте пути вроде `README.md` или `src/main.ts`, с `/`. Абсолютные пути, `..`, обратные слеши, drive paths, внутренние symlink и файлы с несколькими hard links недоступны. `.git`, `node_modules`, `.env*` и известные каталоги/файлы credentials исключены; бинарные, не UTF-8 и слишком большие файлы не читаются. Это текущий контекст на момент чтения, не immutable файл ревизии и не свидетельство выполненной работы.

## Неподтверждённая команда и переключение проектов

Если ответ запуска или решения потерян, сохранённый intent остаётся привязан к исходным projectId, URL, автору, requestId, телу и expectedVersion. Используйте предложенный точный повтор: новая задача или решение не должны отправляться в проект, открытый позднее. Квитанция восстанавливается до проверки новой версии и доступности папки.

Внутренняя навигация сохраняет такой intent в памяти открытого приложения. Долговременное восстановление после reload не обещается; сначала выясните исход отправленного действия. SSE и snapshots каждого проекта имеют собственный cursor: поздние данные A не должны заменять B.

Текущие UI-проверки ведутся в журналах [функционального обзора](plans/functional-status-comments.md), [Base UI](plans/base-ui-selects.md) и [оставшихся критериев](plans/review-followups.md). Для ChatGPT нужны доступный workspace, настроенный tunnel-client и успешный вызов инструмента из ChatGPT.

Файловые инструменты Ouro остаются read-only. Собственные edit/shell tools Cursor/Claude Code определяются разрешениями этих клиентов; наблюдение в дашборде охватывает только явно отправленные в Ouro факты.
