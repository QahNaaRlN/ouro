# Схемы процесса и состояния

Версия alpha.3. [SDD](specs/flow-visualization.md) · [RED/GREEN](plans/flow-visualization.md).

## Процесс внутри спеки

1. Откройте **Спецификации → Процесс**. Выберите ревизию схемы; историческая версия доступна для чтения.
2. **Создать схему** начинает локальный черновик с действием и результатом. Для существующей последней ревизии доступно **Предложить изменение схемы**.
3. В графе выберите узел/ребро для изменения. Режим **Таблица** и формы позволяют выполнить все операции без перетаскивания. Координаты не меняют предметные связи.
4. Определите начальный узел, достижимые шаги и подписанные исходы выбора. Каждый шаг должен иметь путь к результату. Повторная проверка может образовать цикл с выходом. Вопрос и развилка относятся к человеку.
5. **Предложить новую ревизию** сохраняет новый immutable snapshot. Затем выберите предложенную ревизию и отдельно активируйте её. Активация новой версии не переписывает схемы и факты прежних попыток.

При внешнем изменении проекта редактор сохраняет локальный текст. Версия команды не подменяется автоматически: проверьте изменения и явно обновите базу. При появлении новой базовой ревизии сначала нужно изучить её; копию своего черновика можно оставить на экране.

## Связь с реальной работой

MCP `ouro.get_context` отдаёт схему назначенной ревизии. В report tools можно передать `flowNodeId`: узел проверяется именно в этой ревизии. Action допускает action/condition/wait/result, Question/Fork/Blocker требуют одноимённого типа. Фазы одного actionId сохраняют одну привязку.

В просмотре процесса выберите попытку. Подсветка относится только к явно связанным фактам этой попытки/ревизии. Факты без ссылки показаны отдельно. Ребро Fork сопоставляется с chosenOptionId через edge.optionId; выбор человека и подтверждение применения показываются раздельно. В редакторе эти отметки не выдаются за выполнение нового черновика. Результат процесса не заменяет приёмку DoD человеком.

## Состояния

Вкладка **Состояния** показывает отдельные оси исполнения, спеки, запроса и дорожной карты. Текущий узел выделен и подписан. Сплошной отмеченный переход основан на реальном изменении проекции; пунктир показывает возможный путь с условиями. Выберите состояние, чтобы прочитать правила и ответственного. Для чтения без холста есть **Список**.

Разрешение продолжения и ACK агента отображаются отдельно. Схема ничего не запускает по клику. `withdrawn` пока отмечен как зарезервированное состояние без команды, а не как готовая операция.

Основания решений: [BPMN human tasks/gateways](https://www.omg.org/spec/BPMN/2.0.2/PDF), [SCXML](https://www.w3.org/TR/scxml/), [React Flow](https://reactflow.dev/learn/advanced-use/accessibility), [методология Ouro](diagram-methodology.md). Ouro использует собственный процессный контракт и не объявляется BPMN-движком.
