# Контекст Meridian → черновик Ouro

В **«Интеграции → Meridian»** загрузите JSON `meridian-work-scope-view/v1` выбранной работы. Это импорт файла: соединение с нативным приложением и SSO не заявляются.

Для проверки формы доступен [учебный JSON](../tests/fixtures/meridian/scope.json), восстановленный из реальных контрактных тестов Meridian. Он содержит синтетические проект/run/pins и не является снимком настоящей работы. Пакет не добавляет команду экспорта в приложение Meridian; её нативный маршрут описан отдельно в RFC.

1. Выберите JSON до 512 KiB. Проверка включает точный формат, UTF-8, повторяющиеся поля, области, pins и относительные имена путей. Ошибка не создаёт событий.
2. Сверьте проект, репозиторий, workspace, попытку и хеши источника. Откройте источники, объявленные границы и незакрытые вопросы. **«Формат проверен»** означает проверку структуры; подлинность файла независимо не установлена.
3. Уточните название, цель, DoD и остальные поля ожидания. В DoD переносятся формулировка, способ проверки и ожидаемый результат; исходные идентификаторы критериев остаются в происхождении.
4. Нажмите **«Создать черновик спеки»**. Получается идея без активной ревизии и исполнения. На вкладке ожидания доступны неизменяемые pins, SHA256 и скачивание исходного JSON. Изменение ожидания в Ouro сохраняет происхождение.

Если ответ потерян, поля остаются сохранёнными и закрытыми для изменения. **«Повторить тот же импорт»** отправляет прежние requestId и содержание, получает прежнюю квитанцию и открывает именно созданную спеку. Отказ доступа при таком повторе не доказывает отсутствие первого результата: исходный пакет остаётся сохранённым до получения квитанции.

Незавершённая отправка хранится в RAM страницы в области проекта и текущего участника. Можно уйти в другую панель и вернуться: восстановится именно этот пакет. Браузер предупредит при попытке закрыть или перезагрузить страницу с неподтверждённым импортом. Если всё же подтвердить закрытие, RAM-пакет теряется; это не долговечная очередь. Исходные данные не записываются в localStorage. Обычный ещё не отправленный ввод сохраняется между вкладками GitHub/Meridian и обновлениями темы, но не обещает сохранность после ухода из панели или перезагрузки.

Обычный конфликт версии, полученный при первой попытке, позволяет проверить новые события и явно обновить базу перед повторной записью. Для уже неопределённого результата сервер может вернуть `VERSION_CONFLICT` с `details.meridianReceipt:'absent'`: этот ответ выдаётся только после проверки отсутствия квитанции данного автора под блокировкой проекта. Тогда пакет становится доступен для редактирования, а база обновляется только после проверки человеком. Отказ доступа, обычная ошибка или иной 409 такого доказательства не дают. Неожиданный серверный/сетевой отказ сохраняет неопределённость результата.

Пути и названия проверок из файла показываются как данные. Импорт не читает эти пути и не запускает команды. `internal_pins:'verified'` — утверждение исходного снимка, не подтверждение Ouro о настоящей БД Meridian. Статус происхождения — `unverified_import`.

Палитра панели использует реальные статические токены Meridian. Тема выбирается существующим переключателем Ouro; нативная синхронизация темы отсутствует.

Контракт: [SDD](specs/meridian-context.md) · [TDD и результаты](plans/meridian-context.md) · [конкретный RFC нативного моста](proposals/meridian-native-bridge.md).

## API для контролируемой автоматизации человека

`POST /api/meridian/import`, authenticated human, same-origin JSON. Тело содержит только:

```ts
{requestId:string, expectedVersion:number, rawDocument:string, content:RevisionContent}
```

Исходный JSON передаётся строкой без нормализации пробелов/переводов строк; сервер повторно разбирает документ и вычисляет SHA256 его UTF-8 bytes. Предел документа 512 KiB, всего JSON-envelope 2 MiB. Generic `/api/commands` и agent tools не принимают команду импорта или заявленный клиентом origin/digest. Контент черновика проходит ограничения обычной Spec; название — до 200 символов. Непригодный для автоматического отображения контекст явно отклоняется.

Результат — обычная атомарная CommandResult-квитанция с `SpecCreated`, `cursor` и `replayed`. `requestId` уникален в области автора/проекта; повтор должен сохранить всё тело, включая expectedVersion. Отдельный импорт того же файла с новым requestId разрешён: человек может намеренно создать другую спеку.

Полный исходный документ сохраняется только в payload append-only `SpecCreated.meridianSource.rawDocument`. `Spec.origin` содержит компактное происхождение, pins и связь критериев. Сохранённые bytes можно сверить с `documentSha256`; содержимое источника не заменяется последующей ревизией ожидания.
