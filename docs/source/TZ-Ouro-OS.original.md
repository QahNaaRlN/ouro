# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Ouro OS — Control Plane для агентской разработки
**Версия:** 1.0 Ouro | **Кодовое имя:** Ouro (Ouroboros) | **Дата:** 2026-10-28

### 0. Нейминг и Философия
**Название:** Ouro. Происхождение: Ouroboros — змея, кусающая хвост, символ бесконечного цикла.
В контексте проекта: `Ожидание -> порождает -> Реальность -> корректирует -> Ожидание` — виток змеи.
Почему выбрано: 4 буквы, техно-минималистично (cargo, turbo), масштабируется: `ouro-spec`, `ouro-dash`, `ouro-mcp`, `ouro-view`. Продолжает линейку Matryoshka, Legion, Qahnaarin, Mekar.
Логотип: две стрелки в круге, Ожидание и Реальность.

### 1. Введение и Проблема
В эру агентской разработки Git — кладбище. Агент генерирует десятки развилок и блокеров до первого коммита, и это теряется в логах чата. Нужен живой веб-сайт с непрерывным обновлением — Control Plane.

### 2. Концепция Ouro
- **L1 Roadmap Graph** — макро-ожидание, граф спек
- **L2 Spec Card** — микро-ожидание, шаблон SDD, источник правды
- **L3 Reality Graph** — история, внутренняя блок-схема внутри спеки, иммутабельный лог
**Цикл Ouro:** Ожидание порождает Реальность -> Реальность корректирует Ожидание.

### 3. ТЗ на Функционал Ouro

#### 3.1 Шаблон Спеки (Ouro Spec)
- ID: OURO-S-XXX
- Цель / Зачем
- Definition of Done
- Входы / Зависимости
- Ограничения
- Допущения / Assumptions
- Риски
- Комментарий (клапан для хаоса)

#### 3.2 Типы узлов Reality Graph
| Тип узла Ouro | Цвет Human View | Создает | Требует аппрува? |
|---|---|---|---|
| Action | #27272A | Агент | Нет |
| Question | #EAB308 | Агент | Да |
| Fork / Развилка | #A855F7 мерцает | Агент | Да, обязательно с причиной |
| Blocker | #EF4444 пульсация | Агент | Да, обязательно с причиной |
| Success/Fail | #10B981 / #EF4444 | Система | Нет |

#### 3.3 Статусная модель Ouro
- **Roadmap:** Черновик -> Активна -> Заморожена -> Архив
- **Spec:** Идея -> Специфицирована -> В работе -> Заблокирована -> Готово -> Инвалидирована реальностью
- **Reality Node:** Ожидает -> В процессе -> Успех/Провал -> Требует решения -> Пропущен (иммутабельно, только INSERT)

#### 3.4 Realtime протокол Ouro MCP
Агент пишет только в Execution Inbox:
- `ouro.report_blocker({type, expected, actual, reason>=50, impact, proposed_paths})`
- `ouro.report_fork({trigger, context, options>=2, recommendation, reason})`
- `ouro.report_question({question, context})`
- `ouro.report_action({what_done})`
Без reason и альтернатив — событие не создается.

#### 3.5 Флоу аппрува
1. Агент report_fork -> 2. На карточке спеки пульс, линия мерцает -> 3. PENDING карточка в Reality -> 4. Человек выбирает Путь А/Б / Отклонить -> 5. PENDING -> Reality (Одобрено), создается новая спека -> 6. Отклоненные -> Архив Уроков.

### 4. ТЗ на Дизайн Human View для Ouro

#### 4.1 Принципы
- Realtime-first: все что в работе пульсирует
- Color as Language: цвет = статус
- Split View 50/50: слева Ouro Spec, справа Reality Timeline
- Flicker = Interactivity: мерцающая линия = кликабельна

#### 4.2 Токены Ouro Design System
| Токен | Значение | Где |
|---|---|---|
| bg-ouro-primary | #0A0A0B | Фон |
| bg-ouro-card | #141416 | Карточки |
| border-ouro | #242428 | Бордеры |
| ouro-in-progress | #F59E0B + pulse-glow | В работе |
| ouro-blocked | #EF4444 + pulse | Блокер |
| ouro-fork | #A855F7 + flicker | Развилка |
| ouro-done | #10B981 | Готово |

#### 4.3 Анимации
- `edge-ouro-realtime`: stroke-dasharray 8 8, animation dash-move 1.2s linear infinite, filter drop-shadow glow. При активности x2 свечение на 2с.
- `pulse-glow`: box-shadow 0->12px

#### 4.4 Дашборды Ouro View
Метрики: Всего спек, Дрейф Ouro (%), Активных блокеров, Требует решения. Графики: Donut статусов, Bar дрейфа. Легенда всегда видима.
