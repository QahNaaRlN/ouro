## Статусы и полномочия

- Канонические lowercase lifecycle-значения не менялись. Верхний регистр — только отображаемый код.
- `succeeded` означает предъявленный результат попытки. `done` и отдельная ось принятия требуют существующего человеческого `SpecAccepted` для активной ревизии. UI не создаёт такой факт при вычислении статуса.
- `resumeAuthorized` — разрешение продолжения, а не факт running; `stopRequested` — запрос остановки, а не paused. UNKNOWN внешней остановки сохраняется явно.
- Положительное resolved, но ещё unapplied решение само по себе не добавляет запрет resume, которого нет в движке. Применение, разрешение и настоящий ACK фиксируются отдельно; у строгого Flow свои guards завершения шага.
- Доступность start/resume/acceptance проверяется чистым `applyCommand` probe с отбрасываемой временной проекцией. Реальная запись повторно проходит текущие серверные проверки автора, роли, регистрации, версии и scope.
- Старый результат и remediation не становятся текущей primary новой активной ревизии. Время обновления учитывает реальные события и реальные косвенные изменения состояния, с кешированием проекции.
- Неизвестный исход отправки сохраняет исходные project/actor/requestId/expectedVersion/body. Повтор отправляет тот же запрос, включая переход A→B→A.

## Сохранённые ограничения и границы

- Нативный выбор **абсолютного** пути к keyfile не реализован: обычный browser file input его не раскрывает. Секретный файл не читается и не загружается ради выбора. Рабочий путь вводится человеком; отдельный desktop bridge потребует собственного контракта.
- Реестр не содержит достоверного client metadata для старых регистраций. Клиент не выводится из произвольного имени; миграция и новые поля не добавлены ради бренда/иконки. Автоматическое имя новых регистраций не подменяет такие metadata.
- Общие компоненты применены к переработанным формам. Существующий редактор/инспектор Flow содержит свои прежние элементы управления; отчёт не обещает замену всех legacy компонентов приложения.
- Workspace-контроль человеческого шага переведён на `WorkspaceAccordion`/`WorkspaceSelect`/`WorkspaceTextarea`, без изменения guards, labels, runId и draft state; после применения повторён сценарий строгого Flow. Глобальный legacy `SpecFlow` не перерабатывался.
- Совместимый MCP SDK в изолированной фикстуре не доказывает установку или live-подключение пользовательских Cursor/Claude/ChatGPT и внешней модели. Их конфигурация остаётся действием пользователя.
- Локальный preview использует только тестовые данные; реальные пользовательские БД не тронуты. Engine-контракт, миграции, реальные ключи, релиз, production deployment и записи в GitHub не входят в пакет. Figma в этом этапе не изменялась. Полная приёмка пользователя остаётся отдельной от тестов и Git.
