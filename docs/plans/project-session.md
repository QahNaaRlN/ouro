## Implemented boundary

- ProjectSession owns the adopter and stream; registry leases isolate source/project/actor/access/host scope. Each session instance additionally namespaces its read queries. Release cancels/removes only that instance's reads synchronously; a late cleanup cannot clear a newly acquired owner.
- Identity bootstrap has its own mounted/latest-request generation guard. Same-actor refresh creates a new access epoch; reverse-order old identity replies, errors and unmounted completions are discarded. This local generation is not an authentication credential or a server permission grant.
- Query stores the accepted snapshot reference with structuralSharing:false. Its snapshot observers do not fetch. Owner read queries return metadata/cursor without storing a second ProjectState. Snapshot and workspace read kinds have separate single-flight operations but the same admission owner.
- Existing RAM intent/proof logic moved from React into client/http with compatible exports. Both primary command paths use it. Original body/requestId/actor/project/version remain fixed, uncertain outcomes are sticky, and only a valid admitted receipt releases a project command. Non-snapshot binding-recovery audit receipts retain their separate validator.
- Ordinary command/task confirmation additionally proves the receipt's exact original actor/project/requestId and complete event-version interval. A valid foreign snapshot, unbound historical batch or empty response never releases the original intent. The historical empty-receipt recovery gap above remains open rather than being hidden behind generic success.
- Presentation metadata is client-owned: ProjectScope supplies the original slot/label; a readonly lifecycle lookup transfers it only during dispatch. The shared pending record retains it across disposal and web facade changes. Exact retry uses that original record; new writes into an occupied slot are rejected before fetch.
- Error normalization is pure, error reports carry occurrence/code/kind/operation/source/epochs, and reporter throws/rejections are isolated. There is no external telemetry delivery or retention claim.
- Both current UI owners use the runtime. The stable extensionless barrel components/project-session-provider exports the provider; Next root layout wraps it. Parent integration also wraps the standalone Vite WebRoot, above the stable navigation provider, so both primary Vite screens receive one runtime across route navigation. New files follow D11: ProjectRuntimeProvider.tsx, useProjectSession.ts and create-project-runtime.ts.
- The rejected command outcome has optional httpStatus to preserve the existing Flow callback's diagnostic classification. It grants no arbitrary request input or native capability.
