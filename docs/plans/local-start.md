# Локальный запуск · журнал SDD/TDD

29.10.2026 · [Критерии пакета](../specs/local-start.md).

Исходная база — интегрированный `6879b0d` (alpha.11), ранее 245 unit/integration и 57 production E2E. Этот пакет проверяет запуск и установку; прежние результаты не выдаются за проверки новой обвязки.

При чтении выявлены POSIX-присваивания в npm dev/start, Linux-specific browser/temp/artifact пути и отсутствие clone-команды с полной веткой в README. В исходном SDD запланированы RED на launcher до реализации, затем GREEN и проверка чистого клона с сохранением данных между dev и production; результаты ниже.

## RED → GREEN

До реализации две проверки завершились настоящим RED: `npm dev must use a Node entrypoint without shell environment assignments` и аналогичный отказ для start. Сначала ограниченная среда не позволила тестовому subprocess работать; этот запуск не считается RED. Повтор в разрешённой среде показал именно два указанных assertion failure.

После реализации обе проверки GREEN: реальный Node entrypoint запускает fixture Next CLI из пути с пробелами, кириллицей и `&`, сохраняет буквальные аргументы с shell-символами и `OURO_DATA_DIR`, устанавливает loopback и local demo, передаёт код ошибки7. CLI загружается в том же Node-процессе, без shell или промежуточного процесса: сигналы завершения обрабатывает Next. Реальные dev/build/start и чистый клон проверяются следующим gate.

Playwright по умолчанию использует установленный им Chromium, явный `CHROMIUM_PATH` сохранён. Временная БД использует `os.tmpdir()`, два прежних абсолютных screenshot-пути заменены `testInfo.outputPath()`. Нативные Windows/macOS в этой среде не запускались.

## Итоговая проверка

Проверен код `32ce974` в ветке `feat/local-start`; после него менялась только документация.

- `npm ci` успешно выполнен как в worktree, так и в чистом клоне с GitHub по команде из README. Проверочный клон расположен в пути с пробелами `/tmp/ouro local clean`; зависимости берутся из lockfile.
- Полный `npm test`: **247/247**, 0 failed/0 skipped. `npm run typecheck` и `npm run db:check` успешны; DB-check проверил миграции, append-only guards и повторное открытие 35 событий на собственной временной БД.
- Чистый клон: `npm run dev -- --port 3350` → открытие интерфейса с шестью seed-спеками → создание проверочной спеки → остановка SIGINT и освобождение порта → `npm run build` → `npm start -- --port 3350`. Сохранены точные ID/текст и cursor 36; ошибок страницы 0. БД — собственная `.ouro/postgres`, без отдельного PostgreSQL и внешних ключей. Production-процесс также корректно освободил порт после SIGTERM.
- Полный `npm run test:e2e`: **57/57** за 3.2 мин, без повторов или пропусков. Проверялся dev-сервер нового launcher на отдельном порту 3351 и временной БД, `CI=1`. Браузер — установленный Playwright Chrome for Testing 156.0.8078.4, без `CHROMIUM_PATH`. Это отдельный dev-gate; прежние 57 production E2E относятся к предыдущему интеграционному пакету.
- Независимое ревью launcher/README не выявило блокеров. Ссылки/ограничения не обещают выполненный нативный Windows/macOS-прогон.

Ограничения среды не считаются продуктовыми отказами: sandbox не разрешал browser cache в домашнем каталоге, поэтому использован поддерживаемый `PLAYWRIGHT_BROWSERS_PATH` в `/tmp`. PTY-инструмент не доставил первый Ctrl+C внутреннему процессу; после явного SIGINT порт был освобождён. Начальная сборка при ещё живом dev-процессе отброшена, принята только повторная сборка после подтверждённой остановки. Прежние preview и пользовательские БД не менялись.

Прочитанные разделы [Node ESM](https://nodejs.org/api/esm.html) рекомендуют `pathToFileURL` для импорта файловых путей с правильным URL-кодированием. [Playwright browsers](https://playwright.dev/docs/browsers) описывает установку отдельного Chromium, системных зависимостей и перенос cache через `PLAYWRIGHT_BROWSERS_PATH`. Это применено в launcher и инструкции; Next CLI прочитан непосредственно в закреплённом пакете 16.4.3.
