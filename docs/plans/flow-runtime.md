# Статусы проходов · SDD/TDD

29.10.2026 · [SDD до реализации](../specs/flow-runtime.md) · база `70cb0fd`.

Рабочая копия `/workspace/ouro-flow-runtime`, ветка `feat/flow-runtime`. Предыдущие рабочие копии, preview и БД пользователя не используются для разработки. Исходная реализация имеет Action phases, attribution по flowNodeId и четыре независимых автомата; отдельного run/traversal lifecycle нет.

До кода зафиксированы FR01–FR12, opt-in совместимость, последовательный профиль, guards человека и повторов, отдельные pass IDs, конкретные DTO/установка и production browser acceptance. Реализация идёт отдельными пакетами core, MCP/протокол и UI; каждый сначала фиксирует meaningful RED, затем GREEN. Итоги записываются по фактическим проверкам, без объявления fixture/live smoke результатом реального LLM-исполнения.

Прочитаны актуальные локальные инструкции Next.js 16: Playwright рекомендует проверять production artifact; Server Actions выполняются по своей модели dispatch, приложение сохраняет существующие HTTP route handlers. Из первоисточников 29.10.2026 прочитаны SCXML transition guards/selection и run-to-completion, React Flow keyboard/ARIA; каталог OMG подтверждает нормативный BPMN 2.0.2. Принципы human task/exclusive gateway ранее изучены в [методологии](../diagram-methodology.md); новый пакет не объявляется стандартным BPMN/SCXML engine. Повторы в Ouro получают новые run IDs, не изменённую историю прежнего состояния.

Результаты RED/GREEN, ревью и окончательные gates будут дополнены после реализации.

## Реализация и независимое ревью

Функциональный код зафиксирован в `a32e92d`, затем мобильная читаемость — в `8e3e3c0`. Финальная production-сборка создана после обеих правок; после неё менялась только документация. Версия приложения — `0.1.0-alpha.13`, самостоятельного контракта — `0.1.1`.

- Core: 10/10 новых runtime-проверок и 16/16 прежних core-сценариев успешны. Отдельные проходы, один текущий маршрут, owner/authority, циклы с выходом, skip/retry, late fail, runtime/Spec projection и immutable replay проверены.
- Независимая приёмка: 13/13 доменных и 3/3 SQL-проверок успешны. Проверены чужой/старый run, повторные Fork, текущая lineage, late Action, interrupts/withdrawal, физические барьеры, race, receipt lookup после перехода, reopen и прежние hashes.
- Protocol/MCP: сначала 0/2 SDK RED на отсутствии flowProgress/tool mapping, затем 25/25 целевых GREEN. Отдельный итоговый HTTP→stdio discovery — 5/5. Совместимость старых tools-only серверов и post-commit unknown outcome сохранена. Runtime/profile DTO конкретны; canonical каталог содержит 41 JSON Schema, tools — 16.
- Новые Flow-факты первоначально отвергались как источник агентской сводки. Настоящий FlowStepCompleted из выполненной команды дал meaningful RED; после добавления точного allowlist тест GREEN 1/1, источник другой execution по-прежнему отвергается.
- Независимое ревью обнаружило два дефекта учебного адаптера: в UI intent отсутствовал specId, а route ошибочно присваивал nodeId внеплановому вопросу несовпадающего типа. Оба исправлены. Дополнительный simulator interrupt RED HTTP 422 → GREEN; итог 2/2 включает прежний запрет управления внешним агентом.
- TypeScript при интеграции обнаружил narrowing после never-helper и типизацию browser receipt; исправлены до общего gate. Первый общий unit-прогон был 299/300 из-за прежнего ожидаемого списка 15 tools; ожидаемый закрытый каталог дополнен новым разрешённым tool, итоговый полный прогон — 300/300. Это не обход запрета человеческих команд агенту.

## Реальный HTTP и демонстрационный контекст
