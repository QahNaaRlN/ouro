# Проверяемый остаток перехода на Tailwind 4

Исходный снимок — эпик `7c0def1`: 20 CSS-файлов / 1919 правил, 11 frontend-файлов / 41 expression. После workspace, Human View, участников и G1 Roadmap/Reality фактический остаток — **15 CSS-файлов с 990 обычными правилами**, **8 frontend-файлов с 24 style expressions**. Keyframe steps не входят в число обычных правил. Это учёт незавершённой работы, а не полный Tailwind PASS.

G1 удалил `workspace-graphs.css`24 rules и30 graph rules в globals, перенёс11 обычных Roadmap/Reality expressions. Hashes process/state/proposal companions обновлены после review; их оставшиеся AST expressions точно совпадают с прежними записями. Два graph handle rules остаются конечным обычным G2-долгом: consumers — Roadmap, process/state, Reality и оба proposal preview с генерируемыми default-node handles. Shared graph presentation использует public className/slots установленной библиотеки и не создаёт новых technical CSS/inline exceptions.

Workspace-срез удалил четыре старых CSS-файла, перенёс пять статических ProjectSwitcher expressions и FlowPreview wrapper, заменил две записи измеряемой textarea height на CSS custom properties и явно перенёс девять конфликтующих trigger rules специализированных consumers. Их остальные selectors/graph expressions сохраняются у прежних owners. Новый `legacy-shared-defaults.css` содержит конечные 21 rule для ещё не перенесённых вложенных семейств; exact selector/consumer/owner ledger находится в журнале. Он остаётся ordinary debt и должен быть удалён финальным CSS gate. Source hashes затронутых inline-файлов обновлены после review; неизменные graph expressions не объявляются перенесёнными. Обе записи custom-property geometry также пока учитываются консервативным inline-инвентарём.

История участников удаляет31 правило общего participant stylesheet после переноса обеих семей потребителей и сравнения20 PNG. ProjectSwitcher expressions полностью перенесены отдельным workspace-срезом. При объединении сохранены его utilities и явный account surface; удалённый inline record не восстановлен. Реестр сочетает только проверенные изменения обеих историй, без новых широких исключений.

[Машинный реестр](style-debt.json) назначает каждой точной записи семейство реализации: legacy Human View, workspace, graphs либо специализированные панели. CSS хранит отпечаток нормализованного исходника и число правил; inline-запись — отпечаток всего файла и разобранных AST expressions, включая их количество. Изменение referenced константы в том же файле также потребует review. Реестр не применяет glob-исключения и не обновляется при проверке автоматически.

`npm run styles:check` проверяет соответствие этому конечному остатку. Он отказывает при новых/изменённых/устаревших записях, bulk `@apply`, попытке спрятать component CSS в technical theme/base и непроверенных исходных junction/symlink. **PASS означает, что остаток учтён; это не полный Tailwind PASS.**

`npm run styles:final` дополнительно отказывает при любом обычном CSS/inline-долге и `ouro-legacy` layer. На исходном снимке он намеренно завершается отказом. Удаление записи допустимо после переноса соответствующего оформления и фактической проверки его поведения.

Текущие технические CSS-исключения ограничены `app/tailwind.css` и `app/theme.css`: directives/tokens/source discovery и минимальные document base значения. Parser проверяет содержимое этих файлов, а не доверяет названию. Keyframes/fonts могут иметь отдельную точную техническую запись с причиной; обычные selectors там запрещены. Внешний CSS React Flow остаётся внешней зависимостью, его собственные исходники не включаются в этот инвентарь.

Inline-инвентарь намеренно консервативен. Он пока включает и старую вычисляемую геометрию, и theme mapper. Перед финальной квалификацией допустимый остаток CSS custom properties получит отдельные точные записи на уровне expression с обоснованием и проверками. Blanket-исключение всего компонента или всех graph styles не допускается. Этот последующий технический реестр ещё не реализован; текущий final mode не объявляет такие случаи автоматически разрешёнными.

Проверка исходников не доказывает визуальный паритет: размеры, тема, responsive cascade, focus, dialogs и графы по-прежнему требуют browser evidence каждого семейства. Критерии конечного результата задаёт [план миграции](migration-plan.md).
