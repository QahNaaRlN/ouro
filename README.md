# Ouro · Human View

Human View для агентской разработки: ожидание → исполнение → наблюдение → решение человека → уточнение ожидания.

Рабочая версия `0.1.0-alpha.11`: Human View, процессные схемы, визуальные статусные переходы, realtime, решения человека, подключение внешних MCP-совместимых агентов, проверяемые GitHub-коммиты, архив уроков с происхождением новых спек и объяснимые показатели изменения ожиданий, исторический просмотр, уточнения/исправления решений и операторское восстановление после отзыва агента, совместные черновики с отдельными человеческими сессиями, предложения агента с точными источниками и импорт контекста Meridian. История сохраняется в PostgreSQL. Учебный симулятор сохранён отдельно; реальные зарегистрированные агенты имеют собственные ключи и назначения.

[Текущая дорожная карта и границы готовности](docs/roadmap.md) · [Фактические результаты проверок](docs/validation.md). Нативный мост Meridian описан отдельным [RFC](docs/proposals/meridian-native-bridge.md); импорт файла не означает соединение с приложением хоста.

## Локальный запуск

Готовая полная версия находится в ветке **`feat/local-start`**. В `master` пока сохранено исходное описание проекта. Нужны Git и [Node.js 24 LTS](https://nodejs.org/) с npm; проверенная версия закреплена в `.nvmrc` (`24.19.0`). Минимум Next.js — Node 20.9, но для воспроизводимого запуска рекомендуется Node 24.

Команды одинаковы для PowerShell, терминалов macOS и Linux:

```sh
git clone --branch feat/local-start --single-branch https://github.com/QahNaaRlN/ouro.git
cd ouro
npm ci
npm run dev
```

Откройте <http://127.0.0.1:3000>. Остановка — **Ctrl+C** в терминале. Если порт занят: `npm run dev -- --port 3001`, затем откройте <http://127.0.0.1:3001>.

Docker, отдельный PostgreSQL, API-ключи и файл `.env` для этого запуска не нужны. Шрифты включены локально. При первом открытии проекта автоматически применяются миграции PostgreSQL 17.5 через PGlite и создаются шесть учебных спек. Данные сохраняются в **`.ouro/postgres`** после перезагрузки страницы и перезапуска приложения; каталог исключён из Git. Не удаляйте его, если хотите сохранить работу. PGlite допускает один процесс на каталог: завершайте прежний сервер перед новым запуском.

### Запуск собранной версии

Сначала остановите dev-сервер через Ctrl+C, затем:

```sh
npm run build
npm start
```

Адрес тот же: <http://127.0.0.1:3000>. `npm start` требует завершённую сборку и открывает ту же локальную БД. Dev и build используют один `.next`, поэтому не запускайте их одновременно в одной папке.

Для необязательных GitHub/внешних настроек создайте `.env.local` по [.env.example](.env.example) и перезапустите сервер. Внешний PostgreSQL подключается через `DATABASE_URL`; для обычного локального режима он не требуется.

### Проверки для разработки

```sh
npm run typecheck
npm test
npm run db:check
```

Необязательные браузерные проверки — после остановки вашего сервера в этой папке:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright использует свой Chromium и отдельную временную БД. Для собственного установленного Chromium можно задать `CHROMIUM_PATH`. На Linux без нужных системных библиотек используйте установку Playwright `npx playwright install --with-deps chromium`. Результаты и скриншоты находятся в `test-results/`.

[Спецификация локального запуска](docs/specs/local-start.md) · [RED/GREEN и проверка чистого клона](docs/plans/local-start.md).

## Быстро подключить агента

1. В **«Агенты»** создайте регистрацию и скопируйте готовую конфигурацию stdio, Cursor HTTP или Claude Code HTTP. Ключ выдаётся один раз, перезапуск сервера для регистрации не нужен.
2. Добавьте JSON в MCP-клиент. В Ouro активируйте спеку, выберите этого агента и разрешите попытку.
3. Попросите агента прочитать `ouro.get_context` и подтвердить запуск через `ouro.confirm_started`. Вопросы, решения, stop/resume и результат проходят теми же стандартными tools.

[Полная инструкция и шаблоны](docs/agent-quickstart.md) · [Спецификация SDD](docs/specs/agent-connect.md) · [Журнал TDD RED/GREEN](docs/plans/agent-connect.md).

Read-only проверка подключения: задайте `OURO_URL` и `OURO_AGENT_TOKEN_FILE` (либо `OURO_AGENT_TOKEN`) и запустите `npm run agent:check`. stdout не содержит ключа. Stdio bridge также доступен через `npm run mcp`.

Совместимость проверена настоящими официальными SDK Clients обоих транспортов. Конкретные приложения без MCP, OAuth-only клиенты и автоматический запуск самого LLM в этот пакет не входят.

## Процессы и переходы

Human View получает committed снимки через SSE и восстанавливает пропущенную историю после разрыва. Поздний ответ GET не откатывает новую версию; открытые формы сохраняют ввод и базовую ревизию. В roadmap доступны связанные фильтры агента и открытого запроса для графа и таблицы. [Realtime: поведение и ограничения](docs/live-guide.md) · [SDD/TDD](docs/plans/live-updates.md).

**Спецификации → Процесс** открывает версионируемую схему; **Состояния** — граф автомата с текущим состоянием и правилами переходов. Схема редактируется новым предложением ревизии, активация отдельно. [Инструкция по схемам](docs/flow-guide.md) · [SDD/TDD пакета](docs/plans/flow-visualization.md) · [Порядок дальнейшей разработки](docs/roadmap.md).

**История → Исторический cursor** показывает отдельный снимок проекта только для чтения; live-поток продолжает получать новые факты. Человек может запросить уточнение и до применения исправить решение новым связанным запросом. Для экстренно отозванного агента доступны операторская отмена разрешения и отдельное свидетельство фактической остановки. [Правила и сценарии](docs/methodology-guide.md) · [SDD/TDD](docs/plans/methodology-recovery.md).

## Подключить GitHub

В **«Интеграции»** привяжите репозиторий и точную ветку к разрешённой попытке. На сервере задайте `OURO_GITHUB_WEBHOOK_SECRET`; для закрытого репозитория также нужен отдельный `OURO_GITHUB_TOKEN` с правом чтения. В GitHub создайте webhook типа `push`, `application/json`, с тем же секретом и URL из экрана. Внешняя доставка требует доступного HTTPS-адреса сервера.

Подписанная доставка попадает в долговечную очередь; сервер проверяет полный SHA через GitHub API и записывает Action в исходную ревизию. Экран показывает состояние очереди, ошибки, повтор проверки и ссылки на коммиты. Наличие SHA не подтверждает подпись автора, качество кода или DoD. [Настройка, восстановление и ограничения](docs/github-guide.md) · [SDD/TDD](docs/plans/github-evidence.md).

## Архив уроков

В **«Уроки»** человек разбирает наблюдения с точными источниками, формулирует вывод и границы применимости, сохраняет редакцию и отдельно публикует её. Из текущей опубликованной версии можно предложить новую draft-спеку с собственной целью и DoD; источник остаётся связан с точной версией урока. Активация выполняется отдельно. Невыбранный вариант Fork и отклонённый запрос — кандидаты для анализа; они не становятся опубликованными выводами автоматически.

[Как подготовить и применить урок](docs/lessons-guide.md) · [SDD](docs/specs/lessons.md) · [TDD и проверки](docs/plans/lessons.md).

## Показатели ожиданий

В **«Показатели»** задайте исходную и конечную точки истории и область спек. Согласованная формула `100 × K/N` показывает долю исходных утверждённых спек, затронутых изменением контракта, инвалидацией или изменением обязательных предпосылок. Исходная база фиксирована; возврат к прежнему содержанию не стирает случившееся изменение. Новые цели и проверяемые количества показаны отдельно. Без исходной базы процент отсутствует; при неполной или противоречивой истории — недостаток данных. Оценки качества агента и автоматических порогов нет.

Отчёт раскрывает события-основания, исходные ревизии и изменившиеся поля; параметры и результат экспортируются в JSON без записи предметных событий. [Инструкция](docs/drift-guide.md) · [Принятая формула и первоисточники](docs/proposals/drift-metric.md) · [SDD/TDD](docs/plans/drift-metric.md).

## Совместные черновики и участники

В **«Участники»** оператор создаёт отдельные человеческие ключи для входа с HttpOnly-сессиями. В **«Черновики»** несколько людей открывают один документ: Yjs объединяет текст и DoD, сохраняет ввод без связи в открытой вкладке и относительное выделение. Публикация создаёт immutable предложение ревизии, активация отдельно. [Инструкция участников](docs/participants-guide.md) · [Совместная работа и ограничения](docs/collaboration-guide.md) · [SDD/TDD](docs/plans/collaborative-drafts.md).

## Сводки и предложения подключённого агента

Попросите назначенного MCP-агента прочитать `ouro.get_context`/`ouro.get_updates` и вызвать `ouro.submit_proposal` с точными ID первичных событий, sourceCursor, наблюдениями, интерпретацией и ограничениями. Предложение новой спеки также содержит обычное ожидание с DoD; источники ограничены выбранным исполнением.

В **«Предложения агента»** человек читает цитаты, рассматривает сводку или редактирует предложенное ожидание и создаёт черновик. Исходный текст агента сохраняется, активация отдельно. Комментарий агенту виден в исходной попытке; тело новой неназначенной спеки через неё не раскрывается. [Инструкция и ограничения](docs/agent-proposals-guide.md) · [SDD/TDD](docs/plans/agent-proposals.md). Встроенный LLM runner не требуется и не добавлен.

## Контекст Meridian

В **«Интеграции → Meridian»** импортируйте JSON `meridian-work-scope-view/v1`, проверьте выбранные workspace/run/pins, уточните цель и DoD и создайте черновик спеки. Сохраняются исходный JSON, серверный SHA256 и неизменяемое происхождение. Активация и исполнение разрешаются отдельно; импорт имеет явный статус `unverified_import`.

При потере ответа повтор использует то же тело и requestId. Панель сохраняет ввод между источниками интеграции и использует статические токены Meridian по выбранной в Ouro теме. [Инструкция и API](docs/meridian-guide.md) · [SDD/TDD](docs/plans/meridian-context.md) · [конкретный RFC нативного моста](docs/proposals/meridian-native-bridge.md). Это доступная сторона Ouro; live Tauri IPC, SSO и Windows-интеграция требуют отдельного пакета хоста.

## Учебный сценарий с симулятором

1. Откройте pending-развилку в «Требует внимания», выберите вариант.
2. Решение записано, но исполнение ещё ожидает. Отдельно разрешите продолжение.
3. В симуляторе подтвердите продолжение, затем применение решения. Сообщите Action и завершите попытку с evidence.
4. Откройте спеку и примите каждый обязательный критерий DoD с основанием проверки.
5. Перезагрузите страницу и проверьте журнал, причинный граф и экспорт JSON.

Для Blocker одобрение плана не снимает препятствие: разрешите remediation, подтвердите её запуск и успешный результат, затем предъявите evidence устранения. Основная попытка ожидает отдельного разрешения продолжения.

## Дизайн и границы

[Ouro.pen](https://app.pen.dev/s/ZybYRs27l7od_NZYYHASOr_1jXJ9YbL9nyNzQBJgmig) задаёт структуру; [Meridian в Figma](https://www.figma.com/design/dc5MYFfBVYH7AYKb0uXfJW) — визуальные токены, компоненты и темы. Обзор pen.dev и реальные компоненты/токены Figma прочитаны. Мелкие элементы pen.dev не извлечены, пиксельное совпадение не заявляется. Прежние записи о недоступности обоих источников в проектных ТЗ/ТС — исторические.

Next.js 16 / React 19 / TypeScript, домен в `packages/core`, MCP-сервер и bridge в `packages/mcp`. Официальный `@modelcontextprotocol/sdk` публикует 15 инструментов со строгими схемами: чтение назначений/обновлений, отчёты, lifecycle ACK, результат, remediation, отзыв своего запроса, ответ на уточнение человека и source-backed предложения. Зарегистрированный агент видит собственный контекст. tRPC и оркестратор LLM-процессов пока не реализованы. Meridian поддерживается ограниченным адаптером импортированного контекста; нативный host bridge и SSO не реализованы. Встроенный PostgreSQL проверен, внешний `pg`-адаптер отдельно не интеграционно проверялся.

`npm run dev/start` привязаны к loopback и включают локальную подписанную HttpOnly-сессию человека. У каждого зарегистрированного агента отдельный отзываемый ключ; в БД только SHA-256. Отдельные человеческие участники поддерживаются локальным реестром; внешний Browser SSO/RBAC и многоарендность ещё не реализованы. `actor.kind` из тела команды не даёт полномочий. `simulation://` относится только к учебным результатам. Перед обычным отзывом работающего агента нужно подтвердить остановку; экстренный отзыв не останавливает внешний процесс и блокирует его последующие ACK.

Исходные документы сохранены без изменений в [docs/source](docs/source/README.md). Приоритет: прямые уточнения пользователя → дополнения в этой редакции → исходные документы. Конкретные технические решения в дополнениях являются проектными предложениями до их согласования и реализации.
