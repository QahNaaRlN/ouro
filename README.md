# Ouro · Human View

Human View для агентской разработки: ожидание → исполнение → наблюдение → решение человека → уточнение ожидания.

Рабочая версия `0.1.0-alpha.3`: Human View, процессные схемы в ревизиях спек, визуальные статусные переходы, решения человека и подключение внешних MCP-совместимых агентов через Streamable HTTP или stdio. История сохраняется в PostgreSQL. Учебный симулятор сохранён отдельно; реальные зарегистрированные агенты имеют собственные ключи и назначения.

## Запуск и проверка

Node.js 20.9+ (проверено на Node 24). Внешние API и секреты для локального демо не нужны. Шрифты включены локально.

```sh
npm ci
npm run dev
```

Открыть <http://127.0.0.1:3000>. При первом запуске создаётся PostgreSQL 17.5 через PGlite в `.ouro/postgres` и учебный проект с шестью спеками. Перезагрузка и перезапуск процесса сохраняют данные. PGlite допускает **один процесс на каталог**; несколько процессов требуют внешнего PostgreSQL через `DATABASE_URL` из [.env.example](.env.example).

```sh
npm run typecheck
npm test
npm run db:check
npm run build
npm start
```

Браузерные проверки: `npm run test:e2e`. Chromium по умолчанию `/usr/bin/chromium`, другой путь задаётся через `CHROMIUM_PATH`. Тесты используют отдельный каталог БД.

## Быстро подключить агента

1. В **«Агенты»** создайте регистрацию и скопируйте готовую конфигурацию stdio, Cursor HTTP или Claude Code HTTP. Ключ выдаётся один раз, перезапуск сервера для регистрации не нужен.
2. Добавьте JSON в MCP-клиент. В Ouro активируйте спеку, выберите этого агента и разрешите попытку.
3. Попросите агента прочитать `ouro.get_context` и подтвердить запуск через `ouro.confirm_started`. Вопросы, решения, stop/resume и результат проходят теми же стандартными tools.

[Полная инструкция и шаблоны](docs/agent-quickstart.md) · [Спецификация SDD](docs/specs/agent-connect.md) · [Журнал TDD RED/GREEN](docs/plans/agent-connect.md).

Read-only проверка подключения: задайте `OURO_URL` и `OURO_AGENT_TOKEN_FILE` (либо `OURO_AGENT_TOKEN`) и запустите `npm run agent:check`. stdout не содержит ключа. Stdio bridge также доступен через `npm run mcp`.

Совместимость проверена настоящими официальными SDK Clients обоих транспортов. Конкретные приложения без MCP, OAuth-only клиенты и автоматический запуск самого LLM в этот пакет не входят.

## Учебный сценарий с симулятором

1. Откройте pending-развилку в «Требует внимания», выберите вариант.
2. Решение записано, но исполнение ещё ожидает. Отдельно разрешите продолжение.
3. В симуляторе подтвердите продолжение, затем применение решения. Сообщите Action и завершите попытку с evidence.
4. Откройте спеку и примите каждый обязательный критерий DoD с основанием проверки.
5. Перезагрузите страницу и проверьте журнал, причинный граф и экспорт JSON.

Для Blocker одобрение плана не снимает препятствие: разрешите remediation, подтвердите её запуск и успешный результат, затем предъявите evidence устранения. Основная попытка ожидает отдельного разрешения продолжения.

## Дизайн и границы

[Ouro.pen](https://app.pen.dev/s/ZybYRs27l7od_NZYYHASOr_1jXJ9YbL9nyNzQBJgmig) задаёт структуру; [Meridian в Figma](https://www.figma.com/design/dc5MYFfBVYH7AYKb0uXfJW) — визуальные токены, компоненты и темы. Обзор pen.dev и реальные компоненты/токены Figma прочитаны. Мелкие элементы pen.dev не извлечены, пиксельное совпадение не заявляется. Прежние записи о недоступности обоих источников в проектных ТЗ/ТС — исторические.

Next.js 16 / React 19 / TypeScript, домен в `packages/core`, MCP-сервер и bridge в `packages/mcp`. Официальный `@modelcontextprotocol/sdk` публикует12 tools со строгими схемами: чтение назначений/обновлений, отчёты, lifecycle ACK, результат и remediation. Зарегистрированный агент видит собственный контекст. tRPC, оркестратор LLM-процессов и Meridian adapter пока не реализованы. Встроенный PostgreSQL проверен, внешний `pg`-адаптер отдельно не интеграционно проверялся.

`npm run dev/start` привязаны к loopback и включают локальную подписанную HttpOnly-сессию человека. У каждого зарегистрированного агента отдельный отзываемый ключ; в БД только SHA-256. Browser SSO/RBAC и многоарендность ещё не реализованы. `actor.kind` из тела команды не даёт полномочий. `simulation://` относится только к учебным результатам. Перед обычным отзывом работающего агента нужно подтвердить остановку; экстренный отзыв не останавливает внешний процесс и блокирует его последующие ACK.

Исходные документы сохранены без изменений в [docs/source](docs/source/README.md). Приоритет: прямые уточнения пользователя → дополнения в этой редакции → исходные документы. Конкретные технические решения в дополнениях являются проектными предложениями до их согласования и реализации.
