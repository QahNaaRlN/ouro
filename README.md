# Ouro · Живой дашборд агентской разработки

Единый realtime-дашборд выбранного проекта: дорожная карта, подробный процесс выбранной спеки, агенты и попытки, вопросы/блокеры и живая лента фактов. Общий версионированный MCP-контракт позволяет любому совместимому агенту работать с Ouro; ChatGPT — один из вариантов подключения.

Текущая локальная beta-версия — `0.1.0-beta.2`: любая существующая локальная папка как отдельный проект, project-bound подключения MCP-агентов и назначение задач с DoD, queued до настоящего ACK. Выбор папки, подключение и назначение — вход в общий дашборд. `@ouro/protocol@0.1.2` описывает 18 tools, Flow, проходы, ответы и ограниченное чтение файлов. История сохраняется в PostgreSQL; папка не обязана быть Git-репозиторием.

Прежний полный Human View сохраняет учебный проект, GitHub evidence, уроки, показатели дрейфа, исторический просмотр, исправления решений, совместные черновики, предложения с источниками, Meridian import и строгий учёт проходов. Новый проект имеет собственные историю, карту и регистрации, без учебного seed. Файловые tools предоставляют read-only контекст; встроенного LLM runner и файловых write/shell tools нет.

[Текущая дорожная карта и границы готовности](docs/roadmap.md) · [Фактические результаты проверок](docs/validation.md). Нативный мост Meridian описан отдельным [RFC](docs/proposals/meridian-native-bridge.md); импорт файла не означает соединение с приложением хоста.

## Первый запуск релиза

Нужен [Node.js 24 LTS](https://nodejs.org/) с npm; проверенная версия закреплена в `.nvmrc`. Git, Docker, отдельный PostgreSQL и API-ключи для открытия интерфейса не требуются.

1. На [странице выпуска v0.1.0-beta.2](https://github.com/QahNaaRlN/ouro/releases/tag/v0.1.0-beta.2) выберите [ouro-0.1.0-beta.2-source.zip](https://github.com/QahNaaRlN/ouro/releases/download/v0.1.0-beta.2/ouro-0.1.0-beta.2-source.zip).
2. Распакуйте архив и откройте терминал в папке с `package.json`.
3. Запустите одну команду:

```sh
npm run launch
```

Она устанавливает зависимости через `npm ci --include=dev`, собирает production-версию и запускает локальный сервер. Подготовка повторяется при каждом `launch`; данные `.ouro` сохраняются. После `Ready` откройте <http://127.0.0.1:3000/projects>. Терминал оставьте открытым; остановка — **Ctrl+C**. Для другого порта: `npm run launch -- --port 3001`, затем откройте `/projects` на этом порту.

`127.0.0.1` и `localhost` всегда относятся к устройству, где открыта ссылка. Браузер и Ouro должны работать на одном компьютере. Это устанавливаемая локальная версия, а не опубликованный веб-сервис; ссылка из чужой облачной среды не откроет Ouro у вас.

[Установка, проверка архива и перенос данных](docs/first-release-guide.md) · [Обучение в интерфейсе](docs/guided-workspace-guide.md) · [Состав beta-релиза](docs/releases/0.1.0-beta.2.md) · [История изменений](CHANGELOG.md).

### Получить исходники через Git

В `main` находятся принятые релизы, в `dev` — разработка следующей версии. Для точного выпуска используется тег `v0.1.0-beta.2`; прежние `feat/*` ветки и история сохраняются.

```sh
git clone --branch main --single-branch https://github.com/QahNaaRlN/ouro.git
cd ouro
npm run launch
```

Чтобы работать с исходниками в dev-режиме: `npm ci`, затем `npm run dev`. Перед dev/build/test/typecheck переносимый контракт собирается автоматически. Не запускайте dev и build в одной папке одновременно; перед обновлением остановите прежний сервер.

### Данные и повторный запуск

По умолчанию история хранится в **`.ouro/postgres`** рядом с установленным приложением. При первом обращении применяются миграции PGlite/PostgreSQL; шесть учебных спек появляются только в demo-проекте. Добавленная папка получает отдельную пустую историю и неизменяемую привязку к своему пути. Не удаляйте `.ouro`, если хотите сохранить работу; один каталог PGlite обслуживает один процесс.

Новая распакованная папка сама не подхватывает базу старой установки. Для обновления используйте существующий абсолютный `OURO_DATA_DIR` или перенесите копию базы после остановки обоих серверов по [инструкции](docs/first-release-guide.md#обновить-установку-и-сохранить-данные). Также сохраните внешние файлы ключей агентов. ZIP не содержит пользовательских данных или ключей.

Если код и зависимости не менялись после успешной сборки, можно запускать её напрямую: `npm start`. Если сайт не открывается, проверьте, что терминал не завершился ошибкой, уже показал `Ready`, а браузер использует порт из строки `Local`. Одна ссылка сервер не запускает.

Для необязательных GitHub/внешних настроек создайте `.env.local` по [.env.example](.env.example) и перезапустите сервер. Внешний PostgreSQL подключается через `DATABASE_URL`; локальному сценарию он не нужен.

## Обучение в интерфейсе

На странице проектов и в дашборде есть кнопка **«Обучение»**. Она запускает короткую экскурсию: нужная область подсвечивается, экран вокруг затемняется, а подсказка объясняет следующий шаг. При первом посещении появляется небольшое приглашение; экскурсия начинается только по вашему действию.

Можно идти вперёд и назад, пропустить обучение или закрыть его через **Escape**. Кнопка «Обучение» позволяет начать заново. Просмотр подсказок не создаёт проекты, задачи или регистрации, не запускает агента и не принимает DoD. [Пошаговая инструкция и принципы](docs/guided-workspace-guide.md).

Интерфейс стал проще: убраны псевдопереключатель рабочего места, декоративный аватар и повторяющиеся лозунги. Имя текущего участника, рабочие статусы и управление сохранены. Новый [знак Ouro](docs/design/ouro-identity.md) соединяет змею-Уробороса с узлами и переходами графа работы.

## Быстро подключить агента

1. В `/projects` добавьте существующую папку и откройте её дашборд. Выберите Cursor, Claude Code или Claude Desktop, создайте отдельную именованную регистрацию и сохраните одноразовый ключ в локальный файл вне репозитория. Укажите абсолютный путь файла, затем скопируйте или скачайте готовую конфигурацию с точным project URL.
2. Cursor: добавьте запись в `.cursor/mcp.json` открытой папки и включите сервер в Customize. Claude Code: добавьте её в `.mcp.json` либо загрузите отдельный JSON через `claude --mcp-config "/absolute/path/ouro-mcp.json"`. Claude Desktop: Settings → Developer → Edit Config, добавьте запись в `mcpServers` и полностью перезапустите приложение. Существующие настройки сохраняйте; готовые профили их не перезаписывают.
3. Выберите регистрацию, задайте цель и проверяемые DoD, нажмите **«Начать работу»**. Попытка остаётся **«Ожидает агента»** до `ouro.confirm_started`. Передайте агенту выданную инструкцию с точным executionId.
4. Наблюдайте карту, выбранный процесс, агентов, требующие внимания запросы и живые факты на общем экране. Ответ человека, подтверждение применения, разрешение продолжения/ACK, результат и приёмка DoD — отдельные действия.

[Cursor/Claude: подробная настройка и CLI](docs/agent-clients-guide.md) · [Папка и дашборд](docs/project-workspace-guide.md) · [Общий MCP quickstart](docs/agent-quickstart.md) · [SDD/TDD текущего пакета](docs/plans/client-onboarding.md).

Эти клиенты используют локальный stdio bridge без Secure MCP Tunnel. Для ChatGPT сохранён отдельный [пример подключения](docs/chatgpt-guide.md). Ouro, Node/bridge и MCP-клиент должны видеть соответствующие пути и loopback-адрес; пример из облачной среды не подключает приложение на вашем компьютере.

Генератор без изменения настроек: `npm run --silent agent:config -- --client cursor --project-id PROJECT_ID --url "http://127.0.0.1:3000/api/projects/PROJECT_ID/mcp" --key-file "/absolute/private/ouro-agent.key"`. Подставьте значения своего проекта. Для `claude-code` флаг `--entry` печатает одну server entry для `claude mcp add-json`, обычный вывод содержит весь `mcpServers`. [Примеры и правила объединения](docs/agent-clients-guide.md#генератор-из-терминала).

Read-only проверка подключения: задайте `OURO_URL` и `OURO_AGENT_TOKEN_FILE` (либо `OURO_AGENT_TOKEN`) и запустите `npm run agent:check`. stdout не содержит ключа. Stdio bridge также доступен через `npm run mcp`.

Cursor и Claude Code сохраняют собственные edit/shell tools. Read-only относится к файловым tools Ouro; дашборд видит явно сообщённые агентом факты, а не автоматически все действия IDE. Ключ Ouro не заменяет аккаунт/credentials клиента.

Проверки SDK, протокола и интерфейса перечислены в [индексе валидации](docs/validation.md). Конфигурация и bridge-проверка не подтверждают вход в пользовательский аккаунт Cursor/Claude; фактическое подключение проверяется его инструментами. Для ChatGPT дополнительно нужны tunnel/workspace и успешный вызов из самого ChatGPT. [Прочитанные официальные источники](docs/agent-clients-research.md).

## Переносимый контракт Ouro

`@ouro/protocol@0.1.2` содержит Flow/profile-валидаторы, runtime и workspace DTO, полные входные схемы 18 tools, схемы SUCCESS/error-ответов и каталог 49 JSON Schema. Это общий стандарт данных для любого совместимого агента и дашборда Ouro. Агент может прочитать MCP resources `ouro://protocol/manifest` и `ouro://protocol/schemas` через HTTP или stdio. Существующие аргументы tools сохранены; project scope определяется endpoint и ключом, версия контракта независима от версии приложения и MCP transport.

Для отдельной установки создайте tarball:

```sh
npm run protocol:pack
```

Артефакт появится в `artifacts/ouro-protocol-0.1.2.tgz`. В другом проекте установите скопированный файл через `npm install ./ouro-protocol-0.1.2.tgz`. Пакет предоставляет ESM/CommonJS, TypeScript declarations, CLI и JSON-файлы; Next.js и БД ему не нужны. Публикация в npm registry не выполнялась.

[Самостоятельная установка, API и правила версий](packages/protocol/README.md) · [Руководство интеграции](docs/protocol-guide.md) · [SDD/TDD](docs/plans/project-workspace.md). Полный каталог event payload и пакетное построение дорожной карты остаются отдельными этапами; пользователь перенёс локальный вход и общий дашборд перед roadmap batch. Контракт не заполняет пустые схемы автоматически.

## Процессы и переходы

Human View получает committed снимки через SSE и восстанавливает пропущенную историю после разрыва. Поздний ответ GET не откатывает новую версию; открытые формы сохраняют ввод и базовую ревизию. В roadmap доступны связанные фильтры агента и открытого запроса для графа и таблицы. [Realtime: поведение и ограничения](docs/live-guide.md) · [SDD/TDD](docs/plans/live-updates.md).

Клик по спеке в графе или таблице **Дорожной карты** открывает **Спецификации → Процесс** для её активной ревизии, либо последней предложенной при отсутствии активной. Карточка графа также открывается через Enter/пробел. Если схема ещё не описана, интерфейс предлагает создать её; у шести начальных учебных спек готового процесса нет. **Состояния** открывает граф автомата с текущим состоянием и правилами переходов. Схема редактируется новым предложением ревизии, активация отдельно. [Инструкция по схемам](docs/flow-guide.md) · [SDD/TDD схем](docs/plans/flow-visualization.md) · [Исправление перехода](docs/plans/roadmap-process-navigation.md) · [Порядок дальнейшей разработки](docs/roadmap.md).

### Строгий учёт проходов

При разрешении **новой** попытки включите **«Строгий учёт проходов»**. Для поддерживаемой схемы появляется текущий ready-run, а после отдельного ACK запуска агент сообщает start/complete/fail через `ouro.report_flow_step`. Action и человеческое решение сами не передвигают процесс. Граф, таблица и инспектор показывают конкретные runId/visit, причины недоступности и подтверждённые traversals; при повторе старые результаты сохраняются.

Режим последовательный, с одним текущим проходом. Старые попытки остаются legacy, параллельные fork/join и автоматическое выполнение кода не добавляются. Человек отдельно разрешает retry/skip в допустимых случаях; result не заменяет итог execution или human acceptance DoD. [Как включить, ограничения и MCP-примеры](docs/flow-runtime-guide.md) · [Источники и принятые решения](docs/flow-runtime-research.md) · [SDD/TDD](docs/plans/flow-runtime.md).

Внеплановый Question/Fork/Blocker связывается с текущим run и сохраняет человеческие guards; он не изображает новый шаг плана. Неуспех runtime основной незавершённой попытки активной ревизии показывает спеку blocked до допустимого human retry. В собственной симуляторной попытке можно проверить учебные start/complete/fail с явными `simulation://` evidence; симулятор не выполняет работу внешнего агента.

**История → Исторический cursor** показывает отдельный снимок проекта только для чтения; live-поток продолжает получать новые факты. Человек может запросить уточнение и до применения исправить решение новым связанным запросом. Для экстренно отозванного агента доступны операторская отмена разрешения и отдельное свидетельство фактической остановки. [Правила и сценарии](docs/methodology-guide.md) · [SDD/TDD](docs/plans/methodology-recovery.md).

## Подключить GitHub

В **«Интеграции»** привяжите репозиторий и точную ветку к разрешённой попытке. На сервере задайте `OURO_GITHUB_WEBHOOK_SECRET`; для закрытого репозитория также нужен отдельный `OURO_GITHUB_TOKEN` с правом чтения. В GitHub создайте webhook типа `push`, `application/json`, с тем же секретом и URL из экрана. Внешняя доставка требует доступного HTTPS-адреса сервера.

Подписанная доставка попадает в долговечную очередь; сервер проверяет полный SHA через GitHub API и записывает Action в исходную ревизию. Экран показывает состояние очереди, ошибки, повтор проверки и ссылки на коммиты. Наличие SHA не подтверждает подпись автора, качество кода или DoD. [Настройка, восстановление и ограничения](docs/github-guide.md) · [SDD/TDD](docs/plans/github-evidence.md).

## Архив уроков

В **«Уроки»** человек разбирает наблюдения с точными источниками, формулирует вывод и границы применимости, сохраняет редакцию и отдельно публикует её. Из текущей опубликованной версии можно предложить новую draft-спеку с собственной целью и DoD; источник остаётся связан с точной версией урока. Активация выполняется отдельно. Невыбранный вариант Fork и отклонённый запрос — кандидаты для анализа; они не становятся опубликованными выводами автоматически.

[Как подготовить и применить урок](docs/lessons-guide.md) · [SDD](docs/specs/lessons.md) · [TDD и проверки](docs/plans/lessons.md).

## Показатели ожиданий

В **«Показатели»** задайте исходную и конечную точки истории и область спек. Согласованная формула `100 × K/N` показывает долю исходных утверждённых спек, затронутых изменением контракта, инвалидацией или изменением обязательных предпосылок. Исходная база фиксирована; возврат к прежнему содержанию не стирает случившееся изменение. Новые цели и проверяемые количества показаны отдельно. Без исходной базы процент отсутствует; при неполной или противоречивой истории — недостаток данных. Оценки качества агента и автоматических порогов нет.

Отчёт раскрывает события-основания, исходные ревизии и изменившиеся поля; параметры и результат экспортируются в JSON без записи предметных событий. [Инструкция](docs/drift-guide.md) · [Принятая формула и первоисточники](docs/proposals/drift-metric.md) · [SDD/TDD](docs/plans/drift-metric.md).

## Совместные черновики и участники

В **«Участники»** оператор создаёт отдельные человеческие ключи для входа с HttpOnly-сессиями. В **«Черновики»** несколько людей открывают один документ: Yjs объединяет текст и DoD, сохраняет ввод без связи в открытой вкладке и относительное выделение. Публикация создаёт immutable предложение ревизии, активация отдельно. [Инструкция участников](docs/participants-guide.md) · [Совместная работа и ограничения](docs/collaboration-guide.md) · [SDD/TDD](docs/plans/collaborative-drafts.md).

## Сводки и предложения подключённого агента

Попросите назначенного MCP-агента прочитать `ouro.get_context`/`ouro.get_updates` и вызвать `ouro.submit_proposal` с точными ID первичных событий, sourceCursor, наблюдениями, интерпретацией и ограничениями. Предложение новой спеки также содержит обычное ожидание с DoD; источники ограничены выбранным исполнением.

В **«Предложения агента»** человек читает цитаты, рассматривает сводку или редактирует предложенное ожидание и создаёт черновик. Исходный текст агента сохраняется, активация отдельно. Комментарий агенту виден в исходной попытке; тело новой неназначенной спеки через неё не раскрывается. [Инструкция и ограничения](docs/agent-proposals-guide.md) · [SDD/TDD](docs/plans/agent-proposals.md). Встроенный LLM runner не требуется и не добавлен.

## Контекст Meridian

В **«Интеграции → Meridian»** импортируйте JSON `meridian-work-scope-view/v1`, проверьте выбранные workspace/run/pins, уточните цель и DoD и создайте черновик спеки. Сохраняются исходный JSON, серверный SHA256 и неизменяемое происхождение. Активация и исполнение разрешаются отдельно; импорт имеет явный статус `unverified_import`.

При потере ответа повтор использует то же тело и requestId. Панель сохраняет ввод между источниками интеграции и использует статические токены Meridian по выбранной в Ouro теме. [Инструкция и API](docs/meridian-guide.md) · [SDD/TDD](docs/plans/meridian-context.md) · [конкретный RFC нативного моста](docs/proposals/meridian-native-bridge.md). Это доступная сторона Ouro; live Tauri IPC, SSO и Windows-интеграция требуют отдельного пакета хоста.

## Учебный сценарий с симулятором

1. Откройте pending-развилку в «Требует внимания», выберите вариант.
2. Решение записано, но исполнение ещё ожидает. Отдельно разрешите продолжение.
3. В симуляторе подтвердите продолжение, затем применение решения. Сообщите Action и завершите попытку с evidence.
4. Откройте спеку и примите каждый обязательный критерий DoD с основанием проверки.
5. Перезагрузите страницу и проверьте журнал, причинный граф и экспорт JSON.

Для Blocker одобрение плана не снимает препятствие: разрешите remediation, подтвердите её запуск и успешный результат, затем предъявите evidence устранения. Основная попытка ожидает отдельного разрешения продолжения.

## Дизайн и границы

[Ouro.pen](https://app.pen.dev/s/ZybYRs27l7od_NZYYHASOr_1jXJ9YbL9nyNzQBJgmig) задаёт структуру; [Meridian в Figma](https://www.figma.com/design/dc5MYFfBVYH7AYKb0uXfJW) — визуальные токены, компоненты и темы. Обзор pen.dev и реальные компоненты/токены Figma прочитаны. Мелкие элементы pen.dev не извлечены, пиксельное совпадение не заявляется. Прежние записи о недоступности обоих источников в проектных ТЗ/ТС — исторические.

Next.js 16 / React 19 / TypeScript, домен в `packages/core`, MCP-сервер и bridge в `packages/mcp`. Официальный `@modelcontextprotocol/sdk` публикует 18 инструментов со строгими схемами: чтение назначений/обновлений и read-only контекста папки, отчёты, lifecycle ACK, результат, remediation, отзыв своего запроса, ответ на уточнение человека, предложения с источниками и явные факты проходов. Зарегистрированный агент видит собственный project-bound контекст; каждый проект имеет свою историю/cursor/регистрации при общей SQL owner connection. tRPC и оркестратор LLM-процессов пока не реализованы. Meridian поддерживается ограниченным адаптером импортированного контекста; нативный host bridge и SSO не реализованы. Встроенный PostgreSQL проверен, внешний `pg`-адаптер отдельно не интеграционно проверялся.

`npm run dev/start` привязаны к loopback и включают локальную подписанную HttpOnly-сессию человека. У каждого зарегистрированного агента отдельный отзываемый ключ; в БД только SHA-256. Отдельные человеческие участники поддерживаются локальным реестром; внешний Browser SSO/RBAC и многоарендность ещё не реализованы. `actor.kind` из тела команды не даёт полномочий. `simulation://` относится только к учебным результатам. Перед обычным отзывом работающего агента нужно подтвердить остановку; экстренный отзыв не останавливает внешний процесс и блокирует его последующие ACK.
